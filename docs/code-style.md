# 代码规范

本仓库的结构、类型、注释、措辞、格式与提交规范，AGENTS.md 引用本文。prettier、tsc、vitest 能强制的（格式、类型错误、测试通过）不在正文重复，本文只收工具查不出的规则。

规则按四级措辞：「必须」「禁止」是硬性要求，违反会被 review 打回；「应该」默认遵循，偏离时说明理由；「避免」是风格倾向。本文未提到的做法默认自由；修改既有代码时跟随周边风格，即使周边与全文不一致，两可的做法模仿周边代码。

## 结构与抽象

规定函数怎么切、值怎么传、什么该删，方向是删掉不必要的间接层。

- 单用途的简单函数、局部包装必须内联到唯一调用点。
- 完整功能单元（如构建插件对象的函数）应该保留为具名函数。
- 必须直接传值：可选值写 `x?.bundle`，不写 `...(x === undefined ? {} : { onlyBundle: x })` 这类防御性条件展开——类型已经表达的可选性不必再兜一遍。
- 传给外部的回调必须用箭头函数包裹：直接传 `set.has` 这类方法引用会丢 `this`。
- 避免手写探测（如 `existsSync` 回退链），优先用工具自身机制（glob、默认值）。
- 只有单测引用、没有生产调用点的导出必须连同其测试一起删除——测试不是调用点。
- 注释解释的分支从未执行时（参数从未传入、字段只写不读），必须删除分支而不是保留注释。

## 类型

本地类型与官方包类型怎么相处：官方有就不自己写，派生只写差异。

- 本地类型与官方包导出的类型同名或结构相同时，必须删除本地定义、改用官方导出（如 `PiAiModality`、`SchemaNode`）。
- 官方包已定义的类型必须直接使用（type-only 导入，如 `LocaleRuntime`），不手写结构化投影接口——镜像在官方类型演进时没有编译期警告，漂移只在运行期暴露。
- 语义相同但需要收窄、扩展时，必须从官方类型派生、只声明差异字段（如 `PiAiModelEntry extends Omit<PiAiModelProfile, 'input' | 'compat'>`、`Pick<ConfigForm<unknown>, 'getSnapshot' | 'subscribe'>`），不整份手抄官方字段。
- 官方类型藏在合并声明（module augmentation）里时，应该用 `import type {} from '包/remote'` 引入一次让合并生效；官方包未安装时加入 catalog 与 devDependencies（type-only 引用不进产物）。
- 从官方类型派生或取 `keyof` 后，必须确认结果没有坍缩为 `any`：放一个故意类型错误的探针，确认报错点名真实类型名（如 `ModelThinkingLevel`）后删除探针。
- 官方只导出类型、不导出运行时常量时，常量留在本地，用 `satisfies` 绑定到官方联合类型（`as const satisfies readonly ThinkingLevel[]`）。
- 传给宿主挂载的配置字面量应该标注官方 Config 类型（如 `StreamableHttpConfig`），让拼写错误编译期可见。
- wire 投影类型（对官方类型展平并收窄，如 `EffectiveModelFacts`）与为测试注入刻意做的类型擦除是权威定义、不是镜像，禁止为「统一」而删除。
- 结构差异极小的重复接口应该合并：跨构建 half 的同名 wire 契约用 type-only 引用共享一份定义；仅必填性不同的字段用默认值统一。

```ts
// 避免：镜像官方结构，官方类型演进时这里静默漂移
interface ModelProfile {
  id: string
  input: readonly string[]
}

// 改为：直接使用官方类型，或派生时只写差异
type ModelProfile = PiAiModelProfile
```

## 注释

什么时候写、写什么、用什么形式、写在哪；默认是不写。

### 写什么

- 应该用命名回答「是什么」（如 `commitWithConflictRetry`、`materializeWithNewModel`），注释只回答「为什么」与对齐的外部事实。
- 禁止给命名自解释处加注释：接口字段、简单函数、配置项。
- 只保留「外部契约」型注释：一行说明代码对齐的外部事实或来源。

  ```ts
  // 避免：复述签名，删掉后没有信息损失
  /** 设置解析选项 */
  const PARSE_OPTIONS = {}

  // 保留：只补签名说不出的外部事实
  // `!!js` 表达式在官方读取端被 resolve 成字符串；解析口径保持一致
  const PARSE_OPTIONS = {
  ```

- 介绍「这是什么、怎么组合」的内容（包定位、功能列表、文件导览、架构叙述）属于 README，禁止写成代码注释。判据：删掉注释后编辑者会不会做出错误修改——会才是代码注释，不会就属于文档。
- 同一外部事实只在一处声明：字段语义归字段注释、写入策略归调用点、官方语义归类型定义，其他位置不复述。
- 保留的注释必须一句话说完。

### 用什么形式

- `/** */` 与 `//` 按读者位置选择，与内容重要性无关：
  - 事实需要在调用点被看到（字段单位、可空含义、缺省行为、副作用的契约）：必须用 `/** */` 挂在导出声明上，它不可替代的能力只有随导出悬浮显示。
  - 事实只在编辑实现时需要（分支为什么存在、防御的原因、对齐外部行为的常量）：必须用 `//` 写在被约束语句旁。
  - 未导出的内部实现没有调用点读者，不用 `/** */`。
  - 类型签名已经说清的，两种形式都不写。

  ```ts
  // 调用点需要看到的（单位、可空含义、缺省行为）：用 /** */ 挂在导出声明上
  /** 超时毫秒数；缺省时沿用全局配置 */
  export let timeoutMs: number | undefined

  // 只在编辑实现时需要的（分支为什么存在、防御的原因）：用 // 落在被约束语句旁
  // 旧数据可能缺该字段，不能假定存在
  const legacyField = record.legacyField ?? null
  ```

### 写在哪

- 注释必须用中文。
- 约束某个函数、字段、语句的事实必须写在紧邻该声明的位置，不堆在文件顶部。
- 文件头必须不超过一行，且仅当事实真正约束全文件时才允许（如双端内联模块不能使用 `import node:` 与浏览器专属 API）——文件头没有锚点、无人引用，最容易过时堆积。

### 禁止清单

- 禁止这些注释：文件头简介、段落分隔标记（`── xxx ──`）、复述型 JSDoc、历史事故叙述、教程式解释、长篇「为什么」论证。

## 措辞与术语

注释、提交信息与文档的中文用语；一个概念一个词。

- 术语必须统一：一个概念只用一个词（本仓：client half、host half）。
- 必须用自然的技术文档用语：不用英文直译、行话压缩这类生造词（如「行为中性」「形态归一化」）。

## 格式与提交

机械格式由 prettier 强制，本节只补它管不到的提交信息。

- 格式化走 prettier：无分号、单引号、行宽 110，配置在 `.prettierrc.json`。
- 提交信息必须用 Conventional 类型 + 中文主题，如 `feat(dsh-skills): 设置页「Skills 管理」插件`。

## 验证

改动怎么证明是对的，提交前跑什么。

- 重构类改动（内联、合并、删除）必须保持行为不变，以单测通过为准。
- 构建是否成功必须以退出码为准，不以「文件存在、时间戳新」判断——`clean: false` 失败会留下旧产物。
- 默认值与配置改动必须覆盖使用默认值的调用方——显式传值的调用方测不到默认值分支。
- 提交前必须运行与 CI 相同的四项检查：typecheck、test、build、format:check（命令见 AGENTS.md）。
