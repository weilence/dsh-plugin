# GitHub Copilot Pro / Pro+ 额度显示的开源实现与接口边界

核对日期：2026-09-30。本文仅核对 GitHub 官方文档、官方开源源码与第三方项目自己的源码或说明；未使用账号、令牌或实际订阅请求。特别注意：官方已公开 **Copilot SDK 的 `account.getQuota`**；「只能调用私有接口获得个人剩余额度」的旧结论已经过时。本文所说的「额度」必须标明是旧版 premium requests、当前 AI credits、会话／周限额，还是 REST 账单用量，不能混用。

## 首选：GitHub 官方 Copilot SDK（不是公开 Billing REST）

[GitHub 官方 Usage and billing metrics 指南的「Account quota and premium interactions」](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/usage-and-billing#account-quota-and-premium-interactions) 与 [官方 SDK 仓库对应原文](https://github.com/github/copilot-sdk/blob/main/docs/features/usage-and-billing.md#account-quota-and-premium-interactions) 均给出可执行的 TypeScript 用法：`const client = new CopilotClient(); const { quotaSnapshots } = await client.rpc.account.getQuota({}); const premium = quotaSnapshots['premium_interactions'];`。这是 SDK 经其 Copilot CLI runtime 的 **server-scoped RPC**，而非 `api.github.com` 的公开 REST Billing 方法；不需要先创建会话。官方列出的 `AccountQuotaSnapshot` 字段为 `entitlementRequests`（`-1` 表示无限）、`usedRequests`、`remainingPercentage` 和可为空的 ISO 8601 `resetDate`；`quotaSnapshots` 是以 `premium_interactions`、`chat`、`completions` 等运行时字符串为键的映射，必须检查键是否存在。官方明确建议用 `account.getQuota` 提示套餐用量／余额；同页标为 experimental 的是 `session.usage.getMetrics`、`session.metadata.contextInfo`、`session.metadata.recomputeContextTokens`，**不包括** `account.getQuota`。[官方指南 Overview、字段表和选型](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/usage-and-billing#overview)。

SDK 支持默认运行时认证，也支持多租户按用户将其 **GitHub token** 传给 `getQuota`；官方没有在该字段说明中声称 `Plan: read` 或 `read:user` 是 SDK 配额 RPC 的必要权限，不得由其他接口的权限反推。令牌应由本应用经用户授权取得并维护，不读取别的工具的缓存。[SDK 指南「Account quota」的 multi-tenancy 提示](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/usage-and-billing#account-quota-and-premium-interactions) · [CLI 官方认证参考：浏览器／device OAuth、令牌类型及环境变量优先级](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#copilot-login-options)。SDK 源码/文档同时区分每次调用的 `assistant.usage`、单会话 `session.usage.getMetrics` 和账号 `account.getQuota`：前两者不是账号总剩余额度；`totalNanoAiu` 是 nano-AI units，不能直接当成 premium request 个数或美元。[SDK 官方接口分类和换算警示](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/usage-and-billing#accumulated-ai-credit-and-token-totals)。

**新鲜度尚待实测：** [SDK 仓库 issue #2619](https://github.com/github/copilot-sdk/issues/2619) 中用户报告 Python SDK 1.0.8／CLI 1.0.83 的长生命周期进程重复调用得到不变快照，并质疑 `reset_date` 被误写为获取时刻。这是用户复现报告，**并非官方确认或所有版本通性**；不能据此声称每次 RPC 必然命中网络、`resetDate` 必然正确或 SDK 永远缓存。产品须验证安装版本、跨时间调用、月界及后台刷新，用观测时间标记数据过期；不应为了绕缓存提取或复用 CLI 私密令牌。

## 频率、条款与安全界限

- **REST 速率限制和 Copilot 额度是两件事。** [GitHub REST 限速文档](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) 的一般认证用户主限额 5,000 次/小时、未认证 60 次/小时及 secondary limits，并非 premium 请求余额；可读 `x-ratelimit-*`／`retry-after`，403/429 按重置或退避等待，持续请求可导致集成被禁。不能把此 REST 限额宣称为私有 `/copilot_internal/user` 或 SDK RPC 的已公开专属频率；二者的专属 QPS／TTL 未由本次官方资料证实。轮询应节制、缓存并显示数据时效，不能因 `statusLine` 每 300 ms 触发便同步查询网络。
- [GitHub 当前使用限额文档](https://docs.github.com/en/copilot/concepts/billing-and-usage/individuals/usage-limits) 强调 AI credits 和另行的服务速率限制；[旧版 premium requests 监控文档](https://docs.github.com/en/copilot/how-tos/manage-and-track-spending/monitor-premium-requests#viewing-usage-in-your-ide) 还记录旧额度月初 UTC 重置及 Pro/Pro+ 会话／7 日限制。当前账期／账号和 SKU 应以正在使用的服务端返回及相应官方账单为准，不能硬编码「500／1500」之类旧档位，或将 `remainingPercentage` 直接称作「还能调用 N 次」。
- **合规分层：** 官方 REST Billing 和官方 SDK RPC 有公开文档；Copilot CLI／VS Code 使用的内部 `copilot_internal` 路径只从源码得知；仿造编辑器 headers 或抓网页 UI 均是更脆弱的实现。公开源码不等于对第三方的 API 稳定性／使用条款授权。接入前审查 [GitHub Terms of Service](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)、[GitHub API Terms](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#h-api-terms) 和适用 [Copilot 产品条款](https://github.com/features/copilot#faq)，尤其自动访问及令牌用途；本文不对具体使用是否违规作法律断言。
- 不从 VS Code、CLI、OpenCode、CodexBar 或浏览器读取、迁移、复用既有隐私 token/cookie；自行建立用户授权、最小权限、系统凭据存储、撤销与过期处理，服务器侧完成请求，不将 Bearer token 发送到浏览器或记录到日志。个人／组织／企业的付费主体及身份须一致；认证失败、数据缺失、额度耗尽应分别呈现，不静默降级到另一个账号。[官方 Billing REST 的付费主体说明](https://docs.github.com/en/rest/billing/usage)。

**结论：** 显示个人套餐「已用／剩余」优先核对当前 AI credits 口径并采用[官方 Copilot SDK `account.getQuota`](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/usage-and-billing#account-quota-and-premium-interactions)；统计付费主体历史账单使用公开 [Billing REST](https://docs.github.com/en/rest/billing/usage)。CodexBar 式私有接口与第三方插件仅供理解实现，不能取代支持的接口；Claude Code status line 只负责显示。现有 [仓库旧研究笔记](copilot-codex-usage-apis.md) 关于「个人剩余额度无官方机器可读接口」的结论已被新 SDK 文档超越，本文依照用户要求不修改旧文件。
