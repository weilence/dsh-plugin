# 官方 Web 搜索与抓取的实现和替换接入点

本文记录实施前的调研，依据本机 `/Users/luowei/code/deepseek-harness` 的官方源码和智谱官方文档；本地源码链接不是线上 API 的兼容性承诺。调研阶段没有用本仓插件执行端到端搜索；本会话中的智谱工具调用结果仅作样本，不代表稳定协议。后续插件实现见 [智谱搜索提供者](../../plugins/dsh-zhipu-tools/src/search.ts)；下文的「待验证」仍指未以用户凭据或智谱正式兼容性承诺验证的事项。

## 结论先行：分清两种替换

- **事实——替换搜索后端，不替换工具：**模型所见的 `web_search` 由 `@deepseek-ai/dsh-tool-web` 注册，执行时对每条查询调用 `ctx.web.search(...)`；`ctx.web` 独立注册和选择 `WebSearchProvider`。因此只要沿用官方工具的参数、格式、卡片和提示，提供新的搜索 provider 并改变 `web.searchProvider` 选择是更窄的接入点。[工具调用](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L308-L376) · [provider 注册及选择](../../../deepseek-harness/packages/web/web/src/index.ts#L90-L146)
- **事实——替换抓取后端，不替换工具：**`web_fetch` 将 `{ url }` 和中止信号交给 `ctx.web.fetch(...)`；新 `WebFetchProvider` 可在同一 seam 中注册，通过 `web.fetchProvider` 选择，但不能假定自定义 provider 自动具备官方 HTTP provider 的安全限制。[工具调用](../../../deepseek-harness/packages/web/tool-web/src/fetch.ts#L447-L514) · [接口和选择](../../../deepseek-harness/packages/web/web/src/index.ts#L107-L163) · [官方安全策略](../../../deepseek-harness/packages/web/web-fetch-http/src/provider.ts#L56-L140)
- **设计判断——替换工具本身：**若必须改变模型可见的工具名、参数、输出或工具执行逻辑，应先在相应 agent preset 中禁用官方 `tool-web` 的 `search`／`fetch`，再注册自定义工具；不要在同一注册层重名抢占。跨 scope 的同名注册可以遮蔽，但 prompt 与工具定义属于不同注册表，必须单独检查提示是否仍然准确。[开关](../../../deepseek-harness/packages/web/tool-web/src/index.ts#L36-L61) · [注册碰撞与作用域](../../../deepseek-harness/packages/core/tools/src/index.ts#L733-L749) · [作用域遮蔽](../../../deepseek-harness/packages/core/tools/src/index.ts#L1178-L1208) · [提示按名称判断](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L315-L323)

## 1. 官方组合、启用条件与名称冲突

- **事实：**基础组合加载 `@deepseek-ai/dsh-web`，将 `searchProvider` 固定为 `deepseek-official`、`fetchProvider` 固定为 `http`，再加载 DeepSeek 搜索、HTTP 抓取、`tool-web`（`fetch: true`、搜索超时 60 秒）；Web App 关闭宿主层 `tool-web`，在 standard／ptc／cordis 三个 agent preset 中各自加载它。因此修改 host 层那一条禁用的 `tool-web` 配置，不能代替检查实际所用 preset。[基础 patch](../../../deepseek-harness/packages/bundle/base/cordis.patch.yml#L461-L490) · [Web App 宿主关闭](../../../deepseek-harness/packages/bundle/web-app/cordis.patch.yml#L549-L556) · [standard](../../../deepseek-harness/packages/bundle/web-app/presets/standard.patch.yml#L131-L141) · [ptc](../../../deepseek-harness/packages/bundle/web-app/presets/ptc.patch.yml#L133-L143) · [cordis](../../../deepseek-harness/packages/bundle/web-app/presets/cordis.patch.yml#L130-L140)
- **事实——配置覆盖边界：**Loader patch 的 `config` **整体替换，不做深层合并**；层次按 bundle、profile、home、CLI 顺序应用。若以 patch 覆盖 `id: web` 的配置以切换搜索，必须在最终有效配置中**显式保留 `fetchProvider: http`**，否则会失去原本固定的抓取路由；同理如果覆盖目标 preset 的 `id: tool-web` 配置，应写回需要保留的超时／启用项。运行中 DeepSeek provider 自己的 settings section 可更新下一次搜索的端点而不重注册 provider，这是 **provider 内的动态参数**，不是 `web.searchProvider` 选择配置的动态覆盖。[patch 替换语义](../../../deepseek-harness/packages/boot/app-boot/src/config-schema/document.ts#L24-L30) · [应用层顺序](../../../deepseek-harness/packages/boot/app-boot/src/config-schema/document.ts#L155-L159) · [官方配置](../../../deepseek-harness/packages/bundle/base/cordis.patch.yml#L472-L490) · [settings 热更新测试](../../../deepseek-harness/packages/web/web-search-deepseek/tests/settings.spec.ts#L54-L64)
- **事实：**`tool-web` 注入 `tools`、`web`、`systemPrompt`；`search`、`fetch` 配置缺省均为 `true`，分别决定是否注册工具，与 provider 是否可用分离：即使没有搜索 provider，工具 schema 仍在，执行时才报 `WEB_PROVIDER_UNAVAILABLE`。启用的工具携带超时、并发安全标记；默认 30 秒，基础／preset 将搜索改为 60 秒。[配置和注册](../../../deepseek-harness/packages/web/tool-web/src/index.ts#L20-L95) · [无 provider 测试](../../../deepseek-harness/packages/web/tool-web/tests/tool-web.spec.ts#L450-L486) · [工具定义](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L325-L375)
- **事实：**同一个工具注册层里的同名工具会报错，不能指望后注册者覆盖先注册者；scoped 工具可遮蔽继承来的全局或祖先同名工具，顺序不影响遮蔽结果，但同层仍不允许重复。工具过滤仅针对继承来的工具，自己在该 scope 注册的工具会保留；lookup、schema 和执行使用一致的 scope 视图。[注册及拒绝](../../../deepseek-harness/packages/core/tools/src/index.ts#L1057-L1088) · [视图/过滤](../../../deepseek-harness/packages/core/tools/src/index.ts#L1156-L1262) · [双注册与遮蔽测试](../../../deepseek-harness/packages/core/tools/tests/scoped.spec.ts#L70-L107)
- **事实：**`ctx.web` 的搜索与抓取各有自己的 provider ID 命名空间；**同一种能力**重复注册相同 ID 抛 `WEB_DUPLICATE_PROVIDER`，不同能力可以共用 ID。provider 注册与注销属于 fiber effect；仅增添一个不同 ID 的可用 provider，在**现有基础组合明确指定旧 ID** 时不会替换旧 provider。[两个注册表与拒绝重复](../../../deepseek-harness/packages/web/web/src/index.ts#L85-L129) · [命名空间测试](../../../deepseek-harness/packages/web/web/tests/web.spec.ts#L61-L74) · [既有选择](../../../deepseek-harness/packages/bundle/base/cordis.patch.yml#L472-L486)

## 2. `ctx.web` 接口、provider 选择和现有后端

- **事实：**`WebSearchProvider` 为 `id`、无网络调用的廉价 `available()`、`search({ query, maxResults? }, signal?)`；返回 `{ content?, sources: [{url, title?, snippet?, publishedAt?}], truncated }`。`ctx.web.search` 在 provider 超量返回时截断 `sources` 并置 `truncated: true`，没有定义为自动补全缺失字段。`WebFetchProvider` 为 `id`、`available()`、`fetch({ url }, signal?)`；返回最终 URL、HTTP 状态码、`body`（闭合联合 `html`／`text`）、`truncated`。成功取得非 2xx HTTP 响应是结果，不是 seam 错误；调用参数没有 prompt、网页提取配置或 timeout 字段。[请求及结果类型](../../../deepseek-harness/packages/web/web/src/types.ts#L10-L119) · [seam 的截断与抓取](../../../deepseek-harness/packages/web/web/src/index.ts#L131-L200)
- **事实：**选择发生在每次执行时：配置了 ID 时必须找到且 `available()` 为真，否则分别抛 `WEB_PROVIDER_CONFIGURED_MISSING`／`WEB_PROVIDER_CONFIGURED_UNAVAILABLE`；未配置时恰好一个可用 provider 才自动选择，多个抛 `WEB_PROVIDER_AMBIGUOUS`，零个抛 `WEB_PROVIDER_UNAVAILABLE`，不按注册顺序、也不悄悄回退。`web` 服务配置的 `searchProvider`／`fetchProvider` 优先于进程环境变量 `DSH_WEB_SEARCH_PROVIDER`／`DSH_WEB_FETCH_PROVIDER`；当前基础组合已显式配置两者，**仅设置环境变量不能覆盖现有基础组合值**。[配置优先级和解析](../../../deepseek-harness/packages/web/web/src/index.ts#L49-L94) · [异常分支](../../../deepseek-harness/packages/web/web/src/index.ts#L166-L193) · [基础组合](../../../deepseek-harness/packages/bundle/base/cordis.patch.yml#L472-L486)
- **事实：**随基础组合装载的 DeepSeek provider ID 为 `deepseek-official`；它发起独立的 Anthropic-compatible Messages `POST .../messages`，请求体里携带服务端 `web_search_20250305` 工具。这不是 DSH 向主会话 LLM 直接透传 `web_search_20250305`：模型侧 DSH 工具仍是 `dsh-tool-web` 注册的普通 `web_search`。搜索凭据按 DeepSeek account route／`DEEPSEEK_API_KEY` 解析；辅助搜索的 base URL 与聊天 route 独立。`available()` 检查解析器存在及配置形态，并不保证远端凭据实际可用。[provider ID 与请求](../../../deepseek-harness/packages/web/web-search-deepseek/src/provider.ts#L26-L46) · [请求构造与发送](../../../deepseek-harness/packages/web/web-search-deepseek/src/provider.ts#L193-L250) · [凭据与独立端点](../../../deepseek-harness/packages/web/web-search-deepseek/src/index.ts#L79-L145)
- **事实：**源码另有官方 Exa／Perplexity `WebSearchProvider` 示例，分别注册 `exa`／`perplexity`，说明扩展搜索 provider 是既有机制而非重写 `web_search` 的隐式技巧；但在当前基础组合中仍需调整显式 provider 选择。[Exa](../../../deepseek-harness/packages/web/web-search-exa/src/index.ts#L28-L66) · [Exa ID](../../../deepseek-harness/packages/web/web-search-exa/src/provider.ts#L19-L20) · [Perplexity](../../../deepseek-harness/packages/web/web-search-perplexity/src/index.ts#L23-L61) · [Perplexity ID](../../../deepseek-harness/packages/web/web-search-perplexity/src/provider.ts#L19-L20)

## 3. 模型侧 schema、工具策略与会话工具列表

- **事实：**`web_search` 的模型入参只有必填 `queries: string[]`，默认最多 4 条；运行时拒绝空列表、空白查询、超量查询，按原样去除完全重复的字符串。单查询调用一次 `ctx.web.search`，多查询并发执行、失败取消其他查询并等待全部结束；随后按排名轮转、按 URL 去重并按默认 8 条来源上限合并。输出保留可选 `content`、来源与 `truncated`，正文在模型可见结果之前加外部内容不可信提示，末尾要求引用 URL；结构化来源另写入可重放的 `meta` 供 Web 卡片展示。[上限与校验](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L15-L51) · [执行合并](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L218-L293) · [schema、执行和 meta](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L325-L376) · [文本与 meta](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L65-L93) [投影](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L107-L159)
- **事实：**`web_fetch` 的模型入参只有必填非空 `url`，没有模型可控 timeout。`tool-web` 将 HTML 转为 Markdown、过滤部分非正文节点，转换失败／过深时省略原始 HTML；整个输出按默认 200,000 字符上限处理，加不可信提示和状态码标题。工具定义还分别拥有工具卡片的表示和可重放的元信息。[参数校验](../../../deepseek-harness/packages/web/tool-web/src/fetch.ts#L97-L109) · [转换与输出边界](../../../deepseek-harness/packages/web/tool-web/src/fetch.ts#L232-L260) · [正文头与截断](../../../deepseek-harness/packages/web/tool-web/src/fetch.ts#L280-L347) · [输出 schema／执行](../../../deepseek-harness/packages/web/tool-web/src/fetch.ts#L456-L514)
- **事实：**官方 `tool-web` 分别注册 `tool:web_search`、`tool:web_fetch` 系统提示节；文字按该 scope 内能否 `ctx.tools.get(name, scope)` 查到工具动态决定。搜索提示是否建议后续 `web_fetch` 还取决于同一 `tool-web` 实例的 `fetchEnabled` 与 fetch 可见性。重名 scoped 自定义工具若遮蔽官方工具，旧提示不一定随之消失；更换 schema／语义必须连同提示复核或一并关闭相应官方工具。系统 prompt 节同层重名报错，跨 scope 同名节可遮蔽。[搜索提示](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L295-L323) · [抓取提示](../../../deepseek-harness/packages/web/tool-web/src/fetch.ts#L437-L454) · [提示节注册规则](../../../deepseek-harness/packages/core/system-prompt/src/index.ts#L446-L463)
- **事实：**`ToolRuntime` 在 prompt 服务注册一处工具 schema provider；每次组装依据当前 scope 的可见工具、restriction、展示模式生成 wire schema，PTC-only 模式只向模型暴露 `run_code`，其他工具在 SDK 文本中由 `run_code` 调用。`systemPrompt.assemble` 收集全局及作用域 provider、拷贝 schema、排序并生成提示节；agent 每次 pre-step 调用组装，把 `assembly.tools` 放入实际 LLM request，并在工具表变化时记录 request header 与新增／移除消息。因此「注册了工具」不等于「每个会话都看到它」；必须核对具体 agent/preset 的 scope、过滤和 mode。[provider 与模式](../../../deepseek-harness/packages/core/tools/src/index.ts#L848-L858) · [wire schema／PTC](../../../deepseek-harness/packages/core/tools/src/index.ts#L1004-L1029) · [过滤及视图](../../../deepseek-harness/packages/core/tools/src/index.ts#L1090-L1123) · [组装](../../../deepseek-harness/packages/core/system-prompt/src/index.ts#L548-L629) · [会话 pre-step](../../../deepseek-harness/packages/core/agent-loop/src/agent.ts#L267-L285) · [请求及工具变更](../../../deepseek-harness/packages/core/agent-loop/src/agent.ts#L602-L645) · [请求传参](../../../deepseek-harness/packages/core/agent-loop/src/agent.ts#L677-L685)

## 4. 可行替换方案及安全边界

1. **设计判断——优先替换搜索 provider。**在插件 host half 通过 `ctx.web.registerSearchProvider({ id: '<独立 ID>', available, search })` 注册，保持 `web_search` 原样；在**有效的** `web` 行将 `searchProvider` 配成新 ID（不能只注册 provider、只改 `tool-web` 开关，或仅设置被现有配置盖住的环境变量）。将一次 `query`、可选 `maxResults`、中止信号映射到后端，并把结果归一为官方 `WebSearchResult`，不要凭空制造 `snippet`／`publishedAt`。若只想切换搜索而保留官方抓取，在替换 `web.config` 的 patch 中仍须写入 `fetchProvider: http`；两者是独立能力，但配置对象不是深层合并。[provider 契约](../../../deepseek-harness/packages/web/web/src/types.ts#L10-L56) · [注册／选择](../../../deepseek-harness/packages/web/web/src/index.ts#L90-L146) · [基础显式配置](../../../deepseek-harness/packages/bundle/base/cordis.patch.yml#L472-L486)
2. **设计判断——需要替换抓取 provider 时单独决策。**可注册独立 ID 的 `WebFetchProvider` 并更新 `web.fetchProvider`，继续使用官方 `web_fetch` 的 HTML→Markdown、外部内容提示及输出上限；但这些模型输出保护**不是**网络侧 SSRF 防线。官方 HTTP provider 对 URL 限定 HTTP(S) 且拒绝 URL 内嵌凭据、非公共 IP／DNS 重绑定、跨源重定向、超限响应和不支持的 MIME；经代理转发时 DNS 在代理侧完成，本地地址校验／固定不能照搬为对代理出口的保证。接入远端抓取服务时必须在服务端重新定义并验证等价的目标控制、重定向、认证信息和大小／时限策略，不能声称沿用官方 HTTP provider 的安全性质。[URL 限制](../../../deepseek-harness/packages/web/web-fetch-http/src/policy.ts#L17-L67) · [解析、IP 和固定](../../../deepseek-harness/packages/web/web-fetch-http/src/network.ts#L46-L109) · [重定向、代理分支](../../../deepseek-harness/packages/web/web-fetch-http/src/provider.ts#L65-L140) · [内容限制](../../../deepseek-harness/packages/web/web-fetch-http/src/provider.ts#L146-L191) · [默认配额](../../../deepseek-harness/packages/web/web-fetch-http/src/index.ts#L31-L51)
3. **设计判断——确需重写模型工具时：**在目标 preset 的 `tool-web` 配置中关闭被替换的能力，保留另一种能力（若适用），再按 `ctx.tools.register` 定义新工具及对应 prompt／策略；若仅为某一 agent 遮蔽继承工具，可在该 agent 的 scope 注册同名工具，但要验证原提示、scope 限制、PTC 展示模式和 UI 对 `web_search`／`web_fetch` 名称及元信息的既有期待。直接加载第二个同层 `web_search`／`web_fetch` 不是覆盖机制。[各自启用开关](../../../deepseek-harness/packages/web/tool-web/src/index.ts#L36-L95) · [同层冲突](../../../deepseek-harness/packages/core/tools/src/index.ts#L733-L749) · [按 scope 视图](../../../deepseek-harness/packages/core/tools/src/index.ts#L1156-L1262) · [搜索卡片元信息](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L107-L159) · [抓取卡片 meta](../../../deepseek-harness/packages/web/tool-web/src/fetch.ts#L361-L435)

**待验证：**上述替换只是官方源码支持的接入设计，尚未测试插件装载顺序、目标产品 patch 覆盖、实际新后端凭据与网络可达性，亦未对任何自定义抓取 provider 做安全审计。尤其不可把搜索结果／网页正文当成模型指令；官方工具本身以提示节和文本前缀明确标记其为不可信外部数据。[系统提示](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L315-L323) · [共同文本前缀](../../../deepseek-harness/packages/web/tool-web/src/trust.ts#L1-L7)

## 5. 本插件与智谱的实际能力

- **事实：**当前 `@weilence/dsh-zhipu-tools` 只解析凭据并经 `ctx.plugin` 挂载搜索、阅读两台 MCP 服务器，交由 `dsh-mcp-client` 把远端工具公布为 `mcp__<serverName>__<rawName>`；它没有注册 `WebSearchProvider`、`WebFetchProvider`，也没有改变 `web.searchProvider`／`web.fetchProvider`。因此用户的判断成立：现在是「额外增加工具」，官方 `web_search` 仍按默认配置走 DeepSeek 搜索。[当前实现](../../plugins/dsh-zhipu-tools/src/index.ts#L7-L35) · [挂载调用](../../plugins/dsh-zhipu-tools/src/index.ts#L39-L90) · [MCP 工具注册](../../../deepseek-harness/packages/mcp/mcp-client/src/tools.ts#L119-L151) · [官方默认选择](../../../deepseek-harness/packages/bundle/base/cordis.patch.yml#L472-L490)
- **智谱官方资料：**[搜索 MCP](https://docs.bigmodel.cn/cn/coding-plan/mcp/search-mcp-server.md)和[网页读取 MCP](https://docs.bigmodel.cn/cn/coding-plan/mcp/reader-mcp-server.md)给出当前使用的两个 Streamable HTTP 地址和 Bearer 鉴权，描述搜索结果可含标题、URL、摘要等，阅读结果可含正文、元数据等，但**未给出可以据以保证的完整输入 JSON Schema、机器可读输出字段或版本稳定性**。搜索文档称工具为 `webSearchPrime`，而本次会话暴露的是 `mcp__zhipu_search__web_search_prime`；MCP 客户端按服务端实际 `tools/list` 原名注册，不会自动转换命名。具体运行环境须检查 `tools/list`，不能将本文档或本次会话的工具名写死为兼容契约。[注册实现](../../../deepseek-harness/packages/mcp/mcp-client/src/tools.ts#L81-L87) · [实际发现](../../../deepseek-harness/packages/mcp/mcp-client/src/tools.ts#L119-L142)
- **接口匹配判断：**搜索 MCP 的观测结果可在**验证确有 URL 且返回形状可解析后**映射到 `WebSearchResult.sources`；未知结构、非法 URL、上游 `isError` 应明确报错，不能伪造来源。本次会话曾观察到 JSON 文本数组的 `link`、`title`、`content`，但这只是样本，不是智谱承诺的输出协议。Reader MCP 返回的是提取后的内容，官方页面没有承诺真实 HTTP 状态码、最终重定向 URL、原始 HTML 或截断标志；**当前不能诚实地将它实现为 `WebFetchProvider`**，尤其不能补写猜测的 `statusCode: 200`／`truncated: false`。[搜索契约](../../../deepseek-harness/packages/web/web/src/types.ts#L16-L56) · [抓取契约](../../../deepseek-harness/packages/web/web/src/types.ts#L64-L96) · [智谱阅读文档](https://docs.bigmodel.cn/cn/coding-plan/mcp/reader-mcp-server.md)
- **执行路径：**`dsh-mcp-client` 只公开工具定义辅助函数，不公开复用现有连接的直接 `callTool` 接口；经 `ctx.tools.execute()` 转调 MCP 工具虽可拿到 `value`，但会经过模型工具的策略／可见性／执行管道，且 PTC 模式拒绝非 `run_code` 的根调用，不能作为跨所有 preset 的通用 provider 实现。[公开导出](../../../deepseek-harness/packages/mcp/mcp-client/src/index.ts#L24-L28) · [MCP 桥的调用](../../../deepseek-harness/packages/mcp/mcp-client/src/tools.ts#L131-L142) · [PTC 限制](../../../deepseek-harness/packages/core/tools/src/index.ts#L1335-L1353) · [执行入口](../../../deepseek-harness/packages/core/tools/src/index.ts#L1355-L1371)
- **套餐和凭据风险：**智谱[套餐概览](https://docs.bigmodel.cn/cn/coding-plan/overview.md)列出搜索／阅读 MCP 用量，但[适用工具说明](https://docs.bigmodel.cn/cn/coding-plan/tool/others.md)及[使用须知](https://docs.bigmodel.cn/cn/coding-plan/usage-notes.md)限制 Coding Plan 权益用于指定工具，名单未见 DSH。MCP 文档的「兼容 MCP 客户端」只能证明技术上可能接入，不能证明 DSH 场景可按套餐使用；须向智谱确认授权和计费，不能建议绕过限制。个人与团队应使用相应 Coding Plan Key，团队 Key 与平台其他 Key 不通用；目前插件会退而尝试 `ZAI_API_KEY`，并未验证它是否有该 MCP 权限。[凭据回退](../../plugins/dsh-zhipu-tools/src/index.ts#L37-L57) · [智谱搜索 MCP](https://docs.bigmodel.cn/cn/coding-plan/mcp/search-mcp-server.md)
- **凭据传输风险：**官方 web 包工作规范要求携带凭据的 provider 请求在跟随重定向前失败；既有 MCP transport 构造只明确写了 `requestInit.headers`，没有明确设置 `redirect: 'error'`，不能由此推断 MCP SDK 是否安全阻断跨源重定向。新 provider 采用 SDK／HTTP 时须显式保证不会将 Bearer Key 发送到重定向目标，并以重定向响应测试验证。[官方约束](../../../deepseek-harness/packages/web/AGENTS.md#L5) · [既有 transport](../../../deepseek-harness/packages/mcp/mcp-client/src/transport.ts#L40-L44)

## 6. 建议方案与实施门槛

**实施结果与本节的差异：**搜索 provider 已按第 2 条落地（独立 SDK 短连接、严格结果解析），但选择策略改为**设置面板开关 + 两层用户 patch 写入，默认不替换**——第 3 条「bundle patch 直接设置 searchProvider」未采纳：`WebRuntime` 构造时只读一次该值，运行期无法切换，而 bundle 层写死会让所有用户装上即替换。开关的读态以 Loader 内省的运行时生效值为准（来源判定：include 子树 = bundle 可被 home 覆盖；根树 + 文件同 id 行 = 就地改；根树无文件行 = `--patch` 置灰；无条目 = web 未加载置灰），写态就地改生效行（原值记注释、关闭恢复）或 home 新建托管行，写盘后经 HMR patch watcher 在线重整（机制见 [hmr/src/index.ts#L215-L235](../../../deepseek-harness/packages/boot/hmr/src/index.ts#L215-L235)）。第 4 条「搜索替换模式下不再挂载搜索 MCP」同样未采纳——搜索 MCP 工具（`mcp__zhipu_search__web_search_prime`）按需求保留，向模型暴露 `search_domain_filter`、`search_recency_filter` 等官方 `web_search` 入参之外的参数，与 provider 互不替代。

1. **先核实合法性和协议。**向智谱确认 DSH 连接专属 MCP 是否属于 Coding Plan 指定用途、搜索／阅读的扣费及适用 Key；取得许可的测试 Key 后，在隔离测试中记录脱敏的 `tools/list`（原始名称、输入和可选输出 schema）以及搜索正常、空结果、错误、超量和取消时的 `content`／`structuredContent`。若没有可靠的机器可读 URL 及明确的字段映射，暂停「替代官方搜索」承诺，维持现有独立 MCP 模式，不为满足接口而臆造数据。
2. **只接管搜索 provider，不重写 `web_search`。**在 `dsh-zhipu-tools` host half 实现 `WebSearchProvider`，稳定 ID（拟用 `zhipu`），封装连接／重连、凭据解析、远端工具发现、一次查询、严格结果解码与中止传播；`available()` 只做同步的本地可用性判断，不进行网络请求。不要通过 `ctx.tools.execute()` 调用暴露给模型的 MCP 工具：当前官方 `dsh-mcp-client` 没有公开可复用的直接调用接口，因此先在本插件内部用 MCP SDK 管理**一条专供搜索的连接**，不再为同一搜索服务同时创建公开工具连接；若未来宿主提供私有调用接口，再评估迁移。凭据只留在 host，失败报告原始原因及必要的恢复提示；不偷偷切换到 DeepSeek。[provider 接口](../../../deepseek-harness/packages/web/web/src/types.ts#L99-L108) · [provider 选择](../../../deepseek-harness/packages/web/web/src/index.ts#L166-L193) · [当前 MCP 桥生命周期](../../../deepseek-harness/packages/mcp/mcp-client/src/index.ts#L144-L203)
3. **明确选择，不靠注册顺序。**在插件的 bundle patch 中以 `id: web`、`name: '@deepseek-ai/dsh-web'` 作守卫，按最终有效的组合配置设置 `searchProvider: zhipu`，并**同时保留 `fetchProvider: http`**；按配置优先级检查 profile／home／CLI 覆盖和配置 schema 的整体替换语义。仅安装 provider 而未设置 `searchProvider` 不会生效；缺凭据／连接失败时不能静默回退，用户应看到明确错误并能切回原来的 `deepseek-official`。由于包内 bundle patch 会随安装自动生效，发布替换功能前必须在安装说明中明确声明「安装即将默认搜索切至智谱」；如需保留当前「安装只增加 MCP 工具」行为，应提供另外的显式配置步骤，而不能让同一 patch 根据运行时凭据静默猜测用户意图。用户层配置仍可明确选回其他 provider。[当前插件 patch](../../plugins/dsh-zhipu-tools/cordis.patch.yml#L1-L7) · [官方选择规则](../../../deepseek-harness/packages/web/web/src/index.ts#L49-L94) · [patch 替换语义](../../../deepseek-harness/packages/boot/app-boot/src/config-schema/document.ts#L24-L30)
4. **阅读能力分开处理。**第一版继续使用官方 `web_fetch` 加 `http` provider；智谱 Reader 可以保留为**明确标注的独立 MCP 阅读工具**，但不与 `web_fetch` 混称为等价抓取。若目标是不增加重复的模型工具，则在搜索替换模式中不再挂载搜索 MCP；Reader 是否继续暴露单独作为安装选项决定。只有智谱或新的实现能提供真实状态、最终 URL、body 类型和截断事实，并重新验证 URL／SSRF／重定向与大小限制，才另行评估抓取 provider。[官方抓取返回类型](../../../deepseek-harness/packages/web/web/src/types.ts#L64-L96) · [官方 HTTP 抓取安全实现](../../../deepseek-harness/packages/web/web-fetch-http/src/provider.ts#L56-L140)
5. **验证和回退。**用假 MCP 服务及假 credentials 完成搜索／空结果／错误格式／凭据缺失与更新／取消／断连重连／凭据重定向拒绝的 host 测试；验证 `native`、`ptc` 等 preset 中模型仅见一套 `web_search`、参数及搜索卡片仍由官方工具提供，实际远端请求走智谱；检查 `web_fetch` 仍走 `http` 且非 2xx、重定向和 URL 安全语义未变。运行插件测试、类型检查、构建以及仓库全量校验。回退时恢复 `searchProvider: deepseek-official`，卸载／停用插件不应遗留选择到一个未注册的 provider。未经协议与授权门槛验证，不应直接发布成稳定替代功能。[Web App preset](../../../deepseek-harness/packages/bundle/web-app/presets/standard.patch.yml#L131-L141) · [官方工具输出](../../../deepseek-harness/packages/web/tool-web/src/search.ts#L325-L376) · [组合错误语义](../../../deepseek-harness/packages/web/web/src/index.ts#L166-L193)
