# Codex CLI's direct subscription-usage request and DSH credential boundary

Verified from OpenAI's first-party `openai/codex` source at immutable commit [`4994306e9f80448bde85e770a0b0c93d3fee5665`](https://github.com/openai/codex/tree/4994306e9f80448bde85e770a0b0c93d3fee5665), 2026-09-29. This is **source analysis**, not a live API test: no credentials or real subscription HTTP request were used. Local DSH/plugin findings are from the files cited below. Do not mistake a first-party implementation for a published third-party REST contract.

## Answer: yes, a direct first-party HTTP call exists

Codex's `BackendClient::get_rate_limits_many()` calls `get_rate_limits_with_reset_credits()` and then `get_rate_limit_status()`, a **GET** with no request body to `{base_url}/wham/usage` for `PathStyle::ChatGptApi`; the other `CodexApi` style uses `{base_url}/api/codex/usage`. Its client normalizes `https://chatgpt.com` (also `https://chat.openai.com`) to a `/backend-api` base, yielding **`https://chatgpt.com/backend-api/wham/usage`**. [Request and path](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/backend-client/src/client/rate_limit_resets.rs#L69-L80) · [path selection](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/backend-client/src/client/rate_limit_resets.rs#L124-L129) · [base normalization and `get_rate_limits_many`](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/backend-client/src/client.rs#L208-L240) · [URL assertion in OpenAI's test](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/backend-client/src/client/rate_limit_resets_tests.rs#L42-L70) · [method delegation](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/backend-client/src/client.rs#L385-L396).

**Actual first-party header construction, not an independently established server-side minimum:** `Authorization: Bearer <ChatGPT OAuth access token>` and `ChatGPT-Account-ID: <matching ChatGPT account/workspace ID>` are produced from the authenticated `CodexAuth` snapshot by `auth_provider_from_auth`/`BearerAuthProvider`; `User-Agent` is set to Codex's user agent, with `codex-cli` fallback. `Client::headers()` also supports an optional explicit account header and conditional `X-OpenAI-Fedramp: true`. The account ID is conditional on having an ID; **source does not prove that the server invariably rejects a missing account ID**, nor that an API Platform key or refresh token is interchangeable with the access token. Treat the ID as necessary for correct account routing where available, and bind token and ID to the same account. [Auth provider](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/model-provider/src/auth.rs#L306-L324) · [Bearer and account headers](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/model-provider/src/bearer_auth_provider.rs#L31-L45) · [client headers](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/backend-client/src/client.rs#L269-L288).

## Wire response, including absence and multiplicity

The generated **backend** model requires top-level `plan_type`; optional/nullable top-level `rate_limit`, `credits`, `spend_control`, `additional_rate_limits`, `rate_limit_reached_type` are explicit double-options. `rate_limit` contains booleans `allowed`, `limit_reached`, optional/nullable `primary_window` and `secondary_window`. Each present window contains integer `used_percent`, `limit_window_seconds`, `reset_after_seconds`, and `reset_at` (Unix **seconds**, not milliseconds). `credits` contains `has_credits`, `unlimited`, optional/nullable **string** `balance`, and optional approximate-message arrays; it is distinct from `rate_limit_reset_credits` (earned reset credits). Additional limits carry `limit_name`, `metered_feature`, and optional `rate_limit`; the client also accepts supplemental `normal_model_slug`, `account_id`, `user_id`, `rate_limit_upsell` and reset-credit summary. [Top-level generated schema](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/codex-backend-openapi-models/src/models/rate_limit_status_payload.rs#L15-L54) · [limit details](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/codex-backend-openapi-models/src/models/rate_limit_status_details.rs#L15-L35) · [window fields](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/codex-backend-openapi-models/src/models/rate_limit_window_snapshot.rs#L13-L23) · [credit fields](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/codex-backend-openapi-models/src/models/credit_status_details.rs#L13-L40) · [additional bucket fields](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/codex-backend-openapi-models/src/models/additional_rate_limit_details.rs#L15-L28) · [supplemental wrapper](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/backend-client/src/types.rs#L44-L75).

Codex maps `primary_window`/`secondary_window` to client `primary`/`secondary`, converts seconds to minutes, carries `credits`, synthesizes the default `codex` bucket and maps additional buckets. Thus **`used_percent` is display data, not authoritative permission**: first-party code explicitly uses `rate_limit.allowed`, even for `used_percent` 100 or 0 in tests; do not treat `100 - used_percent` as an absolute remaining request count or infer permission when `allowed` is absent. A reached type can distinguish ordinary rate limiting from owner/member credit depletion or workspace usage caps. ## Failure, rate limiting and OAuth refresh are separate operations

For this **usage GET**, the backend client reads status/content-type/body: any non-2xx (including 401, 403 or 429) is an error with the real status/body; transport errors propagate, and malformed JSON yields a decode error. The GET implementation itself has **no demonstrated 429 retry/Retry-After handling or inline 401 refresh-and-replay**; a 200 response with `rate_limit.allowed = false` is a successful quota snapshot, **not** an HTTP 429. Do not turn all network or auth failures into “quota exhausted”; rate-limit polling should respect upstream errors/limits, and a re-login/refresh failure should be explicit. [Request/error/decode flow](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/backend-client/src/client.rs#L295-L313) · [decode and usage method](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/backend-client/src/client.rs#L376-L396) · [permission test](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/backend-client/src/client/rate_limit_resets_tests.rs#L15-L40).

Token refresh is managed by **Codex auth**, not the usage endpoint. The app-server's rate-limit handler obtains `auth_with_http_client_factory()` before requesting usage; `AuthManager::auth()` proactively refreshes managed ChatGPT credentials when needed, guarded by reload/account matching and a lock. It requests refresh via `https://auth.openai.com/oauth/token` and persists updated tokens; permanent classifications include 401/invalid_grant and other known failures, distinct from transient failures. On proactive-refresh failure the auth getter logs and can return the old snapshot, so the subsequent usage GET can still fail: **do not promise guaranteed refresh/retry on usage 401**. External auth and host-provided token modes differ from managed Codex login. [App-server caller](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/app-server/src/request_processors/account_processor.rs#L1186-L1228) · [proactive path](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/login/src/auth/manager.rs#L2389-L2412) · [refresh lock/reload/account guard](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/login/src/auth/manager.rs#L2844-L2939) · [OAuth refresh/persist/error classification](https://github.com/openai/codex/blob/4994306e9f80448bde85e770a0b0c93d3fee5665/codex-rs/login/src/auth/manager.rs#L1598-L1669).

## DSH grant: compatible fields do not imply transferable ownership

The existing plugin's [auth bridge](../../plugins/dsh-models/src/auth.ts#L18-L25) addresses `credentialKey('llm-pi-ai', provider)` and exposes flow metadata plus `credentials.describeRecord()`'s **configured/kind**, not bearer secrets or a grant-consumption API ([source](../../plugins/dsh-models/src/auth.ts#L191-L245)). The installed pi-ai `openai-codex` OAuth provider returns `{ type: 'oauth', access, refresh, expires, accountId }`, obtains `accountId` from the access JWT's ChatGPT claim, refreshes with the `refresh` token, and maps **only** `access` into model-request `{ apiKey }` ([installed pi-ai provider implementation](../../node_modules/.pnpm/@earendil-works+pi-ai@0.87.1_ws@8.22.0_zod@4.6.5/node_modules/@earendil-works/pi-ai/dist/auth/oauth/openai-codex.js#L320-L337), [refresh and auth mapping](../../node_modules/.pnpm/@earendil-works+pi-ai@0.87.1_ws@8.22.0_zod@4.6.5/node_modules/@earendil-works/pi-ai/dist/auth/oauth/openai-codex.js#L419-L449)). The **llm-pi-ai host and its credentials service own the opaque grant and refresh/update lifecycle**: the installed DSH adapter explicitly assigns scope `llm-pi-ai`, stores the pi-ai OAuth payload verbatim as a `grant`, reads it via `credentials.readRecord`, and executes pi-ai's OAuth refresh inside `credentials.modifyRecord` ([installed DSH llm-pi-ai adapter, scope and opaque grant](../../node_modules/.pnpm/@deepseek-ai+dsh-llm-pi-ai@_697d542dcb1f4295c07f7eb0763b8a74/node_modules/@deepseek-ai/dsh-llm-pi-ai/lib/index.js#L1935-L2004), [atomic refresh mutation](../../node_modules/.pnpm/@deepseek-ai+dsh-llm-pi-ai@_697d542dcb1f4295c07f7eb0763b8a74/node_modules/@deepseek-ai/dsh-llm-pi-ai/lib/index.js#L2021-L2064)). `describeRecord` proves presence only. Calling `credentials.resolve('OPENAI_CODEX_API_KEY')` is not equivalent to obtaining the paired `{access, accountId}` or its refresh lifecycle; treating `grant` as a plain secret, parsing storage internals, or copying refresh tokens into this plugin would couple it to another provider's private payload and invite stale writes/account mix-ups. [Plugin's current credential resolution versus Codex app-server](../../plugins/dsh-models/src/usage/index.ts#L23-L27) · [current Codex reader](../../plugins/dsh-models/src/usage/codex.ts#L269-L306) · [local plugin ownership convention](../../plugins/dsh-models/AGENTS.md#L23-L33).

**Feasibility:** The fields are _technically enough_ for a one-shot request if the **credential-owning host** deliberately provides an atomic, refresh-aware, server-side `llm-pi-ai/openai-codex` usage capability (token + matching account ID used only inside that owner, with explicit error handling and no browser token exposure). There is **no direct, safe, documented grant-payload reuse seam evidenced in this plugin**. Prefer the existing **documented local** `codex app-server` `account/rateLimits/read` (already used by this plugin), noting its login is independent of `llm-pi-ai` and cannot automatically show the latter's account; or add a consciously designed first-party owner capability if same-login identity is required. [OpenAI app-server account protocol](https://developers.openai.com/codex/app-server) · [current app-server reader](../../plugins/dsh-models/src/usage/codex.ts#L114-L120) · [same reader checks account type](../../plugins/dsh-models/src/usage/codex.ts#L287-L306).

**Support boundary:** OpenAI publishes the [Codex app-server account/rateLimits/read integration](https://developers.openai.com/codex/app-server) and directs users to the [Codex dashboard/CLI usage displays](https://developers.openai.com/codex/pricing); [OpenAI Platform organization usage](https://platform.openai.com/docs/api-reference/usage) measures API Platform, not ChatGPT subscription quota. This `/backend-api/wham/usage` path is observable first-party CLI **implementation**, not a documented public third-party quota REST API. Its endpoint, token audience, account routing, schema and throttling can change without public compatibility guarantees; the repository's generated backend models and additional hand-written compatibility wrapper themselves demonstrate evolving wire shape. Use the supported local app-server boundary unless explicitly accepting this private-service risk. No live HTTP behavior or server-enforced minimum headers were verified here.
