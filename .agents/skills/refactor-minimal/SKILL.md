# 重构精简

目标：代码只保留必要的抽象，注释只保留外部契约。

## 注释

- 命名自解释的（接口字段、简单函数、配置项）禁止加注释。
- 应该优先用命名解释而不是注释：名字回答"是什么"（如 `commitWithConflictRetry`、`materializeWithNewModel`），注释只回答"为什么 / 对齐什么外部事实"；复述名字或签名的注释禁止保留。
- 只允许保留"外部契约"型注释：一行说明代码对齐的外部事实或来源。范例：

  ```ts
  // client 基座 external，对齐 DSH 宿主 seed 表（packages/client/web/src/platform.ts）
  const PLATFORM_CLIENT_EXTERNALS = [
  ```

- 注释必须放在实现位置：约束某个函数 / 字段 / 语句的事实紧邻该声明，禁止堆在文件顶部；文件顶部只允许约束整个模块且无单一落点的事实（如类型镜像的真源声明、文件独立存在的理由）。
- 介绍"这是什么 / 怎么组合"的内容（包定位、功能列表、文件导览、架构叙述）属于 README，禁止写成代码注释。判据：删掉注释后编辑者会不会做出错误修改——会才是代码注释，不会就是文档。
- 同一外部事实只允许在拥有它的位置声明一次（字段语义归字段注释、写入策略归调用点、官方语义归类型定义），其他位置禁止复述。
- 禁止以下注释：文件头简介、段落分隔标记（`── xxx ──`）、复述型 JSDoc、历史事故叙述、教程式解释、长篇"为什么"论证。
- 保留的注释必须一句话说完。

## 代码

- 单用途的简单函数 / 局部包装必须内联到唯一调用点。
- 完整功能单元（如构建插件对象）应该保留为具名函数。
- 必须直接传值：用 `x?.bundle`，禁止 `...(x === undefined ? {} : { onlyBundle: x })` 这类防御性条件展开。
- 传给外部的回调必须用箭头函数包裹（直接传 `set.has` 这类方法引用会丢 `this`）。
- 应该优先使用工具自身机制（glob、默认值），而非手写探测（如 `existsSync` 回退链）。
- 结构差异极小的重复接口应该合并（跨构建 half 的同名 wire 契约用 type-only 引用共享一份定义）；仅必填性不同的字段应该用默认值统一。
- 术语必须统一，一个概念只用一个词（本仓：client half / host half）。
- 只有单测引用、没有生产调用点的导出必须连同其测试一起删除。
- 注释解释的分支从未执行时（参数从未传入、字段只写不读），必须删除分支而不是保留注释。

## 类型

- 本地类型与官方包提供的类型同名或同形状时，必须删除本地定义改用官方导出（如 `PiAiModality`、`SchemaNode`）。
- 语义相同但需要收窄 / 扩展的必须从官方类型派生，只声明差异字段（如 `PiAiModelEntry extends Omit<PiAiModelProfile, 'input' | 'compat'>`、`Pick<ConfigForm<unknown>, 'getSnapshot' | 'subscribe'>`），禁止整份手抄官方字段——手抄镜像会随官方演进漂移。
- 官方类型藏在合并声明（module augmentation / typert 生成面）里时，应该用 `import type {} from '包/remote'` 显式激活；官方包未安装时应加入 catalog 与 devDependencies（type-only 引用不进产物）。
- 从官方类型派生或取 `keyof` 后，必须防 any 塌缩：放一个故意类型错误的探针，确认报错点名真实类型名（如 `ModelThinkingLevel`）后删除探针。
- 官方只导出类型不导出运行时常量时，常量留在本地并用 `satisfies` 绑到官方联合（`as const satisfies readonly ThinkingLevel[]`）。
- 传给宿主挂载的配置字面量应该标注官方 Config 类型（如 `StreamableHttpConfig`），让拼写错误编译期可见。
- wire 投影类型（对官方类型的展平收窄，如 `EffectiveModelFacts`）与刻意的测试缝类型擦除是所有者不是镜像，禁止为"统一"而删除。

## 措辞

- 规则必须用"必须 / 应该 / 禁止"分级表述：必须是硬性要求，应该保留判断空间，禁止仅用于有害或误导的做法。
- 必须用自然的技术文档用语，禁止生造词（英文直译、行话压缩，如"行为中性""形态归一化"）。

## 验证（必须全部通过）

1. 重构必须保持行为不变，以单测通过为准。
2. 禁止以"文件存在 / 时间戳新"判断构建成功（`clean: false` 失败会留旧产物），必须以退出码为准。
3. 默认值与配置改动必须覆盖使用默认值的调用方：显式声明的调用方测不到默认值分支。
4. 必须跑全套检查：typecheck / build / test / format:check。
