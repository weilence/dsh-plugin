# @weilence/dsh-notify

DSH web 插件 —— 回合完成通知。模型回合处理完成时弹操作系统级桌面通知，
离开页面也能第一时间知道「跑完了」。

## 功能

- **系统通知（纯 client 实现，无自建传输）**：实时订阅宿主转发的回合状态事件（无轮询、近乎零延迟），回合完成即用 Notification API 弹系统级通知。点击通知切换到对应会话并聚焦页面。
- **提问等待回答通知**：模型发起提问（含计划审批）等待用户回答时通知，正文为首个问题文本（多题汇总数量）。
- **工具审批等待批准通知**：工具操作需要用户批准（命令执行审批、沙箱提权、工作区外写入等）时通知，正文为「等待批准：<工具名> · <原因>」。
- **前台浏览时静默（固定行为）**：您正停留在本页（标签页可见且窗口聚焦）时不弹通知；事件发生时在前台的，约 3 秒后复查一次，期间切走会补弹，仍在浏览则静默。
- **设置页面**：设置面板新增独立「完成通知」菜单页——通知权限请求、开关与测试按钮。
- 仅主代理会话的完成、提问与审批会通知；子代理不通知。通知标题为会话名。

### 投递语义

转发事件为 best-effort、不回放：页面关闭期间的事件没有接收方、不会补发；连接闪断期间的完成事件会丢失。仍在等待的提问 / 审批会在重连后回放，因此页面重开时「等待回答 / 批准」仍会补通知一次。

## 安装

宿主 `package.json` 的 `dependencies` 与 `dsh.profile.bundles` 均加入
`@weilence/dsh-notify`。启动时 profile boot 会自动合并包内的 `cordis.patch.yml`。

## 使用

安装重启后打开 Web UI 设置 →「完成通知」：

1. 首次使用点「请求通知权限」并在浏览器弹窗中允许；
2. 保持开关为「通知：开」；
3. 「测试」按钮可立即验证系统通知。

注意：浏览器页面需保持打开，页面关闭即无接收方；若系统级收不到通知，
先检查操作系统对浏览器的通知授权。无持久化配置；面板提供运行态开关。
