# dsh-mcp 已确认决策

本文件承载已确认的行为决策与取舍理由（为什么是这个行为）；行为表现见 [docs/spec.md](spec.md)，实证与禁止事项见 [docs/traps.md](traps.md)。

- 事实源与生效机制：以两份 `.mcp.json` 为持久化事实源，挂载走 Loader 运行时 API 当场生效——没有 HMR 依赖、没有重启需求，区别于经 patch watcher 的两层用户 patch 链路（全仓机制见根 `docs/patch.md`）。
- 动态条目只存内存、重启重放：Loader 根树不可持久化，持久化只认两份文件，不另设插件私有存储。
- 作用域收窄：cordis.patch.yml 与其他插件挂的 MCP 行不读取、不展示、不修改——挂载 diff 只认自己 `mcpx-` 前缀 id，触碰外部行会劫持 / 破坏宿主与其他插件的挂载。
- 工作区档命名与位置对齐 Claude Code / Cursor 的项目惯例（`<工作区>/.mcp.json`），跟随主视图会话的工作目录。
- 同名遮蔽语义（工作区档生效、全局档标记遮蔽不挂载、删除工作区档条目即恢复）对齐 Claude Code 的项目覆盖语义。
- 保存前强制连接检查 + 显式跳过：把连不上的配置拦在落盘前；失败展示原因，再点一次「保存」显式跳过，任何输入变动重置跳过标记。
- 无效条目不代改：文件里原样保留（写回身份不变），面板只展示原因与允许删除，修复走手工改文件。
- 过渡态用轮询跟进而非事件推送：宿主侧 fiber 转变没有任何推送通道（Loader 不发状态变化事件），轮询是唯一自动跟进手段；落定即停、面板关闭（无订阅者）即停。
- stdio 探测选 cross-spawn：与官方 StdioClientTransport 同源、args 直接传递不经 shell 插值，两平台行为一致（偏离的后果见 docs/traps.md）。
