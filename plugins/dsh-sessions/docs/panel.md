# dsh-sessions 面板与导入域

本文件承载面板与导入域——会话列表 / 卡片 / 行操作 / 批量操作 / ZIP 导入 / 迁移与预设弹窗 / 通知通道（`src/client.tsx` 与 `src/client/*`，host 侧 `src/archive.ts` / `batch.ts`）——的行为语义、陷阱与取舍。磁盘手术域见 [docs/surgery.md](surgery.md)，测试地图见 [docs/tests.md](tests.md)。

## 会话面板

- 侧栏「会话」全局面板：搜索 / 过滤全部会话，归档 / 恢复、跨工作区迁移、迁移 Agent 预设、批量操作、导入宿主导出的会话 ZIP、级联删除；侧栏会话行「…」菜单提供「迁移到工作区」入口。
- `src/client.tsx` 是 client half 入口：会话面板主体（搜索 / 过滤 / 排序、行操作）与导入弹窗（`ImportDialog`）。
- 数据全部来自官方客户端快照（`ISessions.list` + `IWorkspaces.list`），搜索 / 过滤 / 排序纯客户端实现，不读聊天内容；subagent 回退行仅存在于 byId，列表构建时并入。
- 列表用 `@dsh-plugins/client-ui` 的 `CardList` / `ExpandableCard`（与 dsh-skills 同款可展开卡片）；行操作：归档 / 恢复（官方命令）、迁移到工作区、迁移 Agent 预设、删除（级联子会话，需确认）。
- 行操作编排在 `src/client/store.ts`；迁移弹窗经 `src/client/migrate.tsx` 的桥同时服务侧栏菜单与面板行内入口；`src/client/preset.tsx` 是预设迁移弹窗（`PresetDialog`）。
- `src/client/api.ts` 是 client 侧 HTTP 封装；`src/client/locales.ts` 持有多语言词典（组织方式见仓库根 docs/i18n.md）；`src/client.module.css` 与 `src/css-modules.d.ts` 是面板局部样式与类型声明。
- 面板原语、字段契约等通用约定见仓库根 docs/panel.md；面板根是 `main` keyed 页面，用共享 `PanelPage` 页壳承载标题与说明，内层 `Panel` 无头部只作纵向间距容器。

## 通知通道

- 提示信息一律优先 notice：面板行操作与批量摘要走共享通知套件（store 的 `notices` 通道 + `NoticeToast`，组件态随面板卸载消亡不重放）；导入 / 迁移 / 预设弹窗内的提示是弹窗局部组件态 `Toast`（5 秒、文本作 key 重开计时）；均不放行内常驻。通知通道划分通则见仓库根 docs/panel.md。
- 批量结果弹窗本身跨挂载存活，由面板卸载清理（`dismissOutcome`）防重放；导入弹窗的逐文件结果清单是报告不是提示，保持列表呈现（取舍：清单是结果记录，不是操作反馈）。
- 宿主不发布会话移除事件，账本清理后侧栏会解除隐藏过期摘要：删除成功后客户端必须全量刷新官方会话列表（`sessions.refresh`）。

## 批量操作

- host 编排在 `src/batch.ts`、UI 在 `src/client/batch.tsx`（工具条、删除预览、迁移 / 预设弹窗、结果弹窗）；删除 / 迁移 / 预设走 `/batch` 单路由：请求去重与 ≤200 上限前置校验，整批持存储互斥逐项串行，单项闸门失败只记为该项失败并继续。
- 删除维护级联已覆盖集，父子同批时后到者标记 `cascaded`。
- 归档 / 恢复不走 host：客户端循环官方命令（取舍：宿主控制器已串行化，客户端循环即可）。
- 批量 UI：进入批量模式后卡片行首出现选择列（共享卡片 `selection`——整列纵向热区点击即勾选，行头其余区域仍是展开），行内动作隐藏；选择集跨过滤保留、退出即清空；「选中本筛选结果」只取当前可见行。
- 批量删除先经预览弹窗（列目标 + 运行中标注）；逐项明细（成功摘要 / 失败原因 / 级联数）进结果弹窗分组呈现，「重试失败」对失败 id 原参数重跑；操作级反馈走 notice 一句话汇总。

## ZIP 导入

- host 侧解析与写入在 `src/archive.ts`——ZIP 解析、整份校验（CRC / 附件 SHA-256 / 谱系 / 格式语义）与冷会话写入。
- 流程：来源机器等待主会话及子会话停止后用宿主自带的下载功能导出 ZIP → 面板「导入」选择目标工作区和一个或多个 ZIP（没有工作区先在左侧列表添加）→ 确认 ZIP 来源可信后导入，逐份校验、某份失败继续处理其他 ZIP → 成功的普通会话关联到所选工作区 → 完成后刷新会话列表。
- 只创建目标上不存在的冷会话：同 ID 内容完全相同则跳过，内容不同拒绝导入（不覆盖、不合并分叉历史）；目标上同 ID 会话必须未加载到内存。
- 写入前完成整份归档校验（CRC、附件 SHA-256、谱系、格式语义），目标发生变化时拒绝写入。
- 接受宿主官方 ZIP：根日志、后代会话日志及引用附件，当前只支持 V4。
- 限额（每份 ZIP）：压缩 64 MiB、总解压 256 MiB、单条目 64 MiB、单份日志 16 MiB、条目数 4096、会话数 256、单会话事件 100,000；请求体限制与导入一致。
- ZIP 未脱敏、未加密（可能含指令、推理记录与敏感附件），点击导入表示确认来源可信，不是隔离机制。
- 整批导入不是一个全局事务：单份日志由宿主的持久化服务发布，中途失败可能留下已保存会话，界面报告已完成数量，不自动回滚用户数据。
- 陷阱：导入不是隔离机制——校验语义（CRC / 附件 SHA-256 / 谱系 / 格式语义）与限额是安全边界的一部分，不得为让数据通过而放宽。
