# @weilence/dsh-sessions

在 DSH 设置页提供「会话迁移」：导出完整 ZIP、在另一台机器上离线恢复，或将本机会话传输到 dsh-remote 已连接的远端。

**这是手动快照迁移，不是双向自动同步。** 保留会话 ID、完整事件日志、子会话和引用附件；只创建目标上不存在的会话，内容完全相同则跳过。同一 ID 的内容不同就拒绝导入，不覆盖，也不合并分叉历史。

## 安装与启用

需要 DSH `0.2.0-rc.2` 的会话、附件、工作区及 Web 连接服务。此版本在本仓开发，尚未因本次开发自动发布到 npm。

从仓库安装开发版本：

```bash
pnpm install
pnpm --filter @weilence/dsh-sessions build
# 将路径替换为本机实际插件目录，profile 替换为正在使用的 profile。
dsh plugin --profile <profile> add /absolute/path/dsh-plugins/plugins/dsh-sessions
```

安装后重启宿主，并刷新页面。宿主侧的新路由和服务不能仅靠刷新浏览器生效。

在线传输还需要：

- 本机安装本仓 `@weilence/dsh-remote` `0.2.0` 并重启宿主；旧版没有会话传输通道。本次版本号升级也确保连接部署时不会因远端旧版本号相同而跳过更新。
- 在「远程开发」中连接目标机器。
- 远端的 `web` profile 启用同版 `@weilence/dsh-sessions`，并重启远端实例后重新连接。可先通过「同步插件」以本地传输方式安装开发版本；若宿主没有在线应用新插件，需手动重启远端实例。
- 目标工作目录已经存在；项目代码、模型凭据、工具和所需插件另行准备。

## 离线迁移

1. 等待主会话及子会话停止运行。在「会话迁移」中选择本机会话，点击「导出 ZIP」；也可直接使用宿主右上角的下载会话功能。
2. 将 ZIP 复制到目标机器，确认文件完整。在目标的「会话迁移」中选择 ZIP。
3. 输入目标机器上已存在的绝对工作目录，点击「预览导入」。目录不能留空，也不会默认沿用来源机器的路径。
4. 检查新增、已一致或冲突的会话，阅读权限提示并确认来源可信，再点击「确认导入」。
5. 成功的普通会话关联到目标工作区；导入不会自动打开或运行会话。检查环境和历史权限后，再从工作区中打开会话继续。

目标上同 ID 的会话必须未加载到内存；已打开或正在运行的会话会被拒绝。若需要重启目标宿主释放会话，请先妥善结束目标上的其他工作。子会话保留其身份及父子关系，不会改成普通主会话；能否继续执行取决于宿主的子会话恢复契约。

## 传输到已连接远端

1. 在「本机会话」中选择来源。在「传输到远端」中选择连接，并填写远端的绝对工作目录。
2. 点击「预览导入」。本机导出一次快照，经现有 SSH 隧道交给远端校验并比对目标数据。
3. 检查远端返回的预览，确认档案来源可信，再点击「确认传输」。提交使用预览时的同一份快照，不会悄悄换成来源会话的后续内容。
4. 打开远端页面后刷新，查看目标工作区中的会话。

不会重新建立 SSH 引擎，也不会从租约文件猜测连接状态。传输只能调用会话预览与导入两条固定路径；启动 token 先换取绑定隧道地址的 Cookie，远端再通过宿主认证和插件协议标记验证请求。

连接正在部署、断开或执行其他操作时，入口仍保留，但传输不可执行。远端没装插件、认证失败、连接变化和写入错误都会显示实际原因。

## 宿主下载是否适合导出

适合。宿主下载的不是 Markdown 或屏幕上的聊天文本，而是正式 ZIP：根日志 `session.v4.jsonl`、`subagents/<id>/session.v4.jsonl` 及 `media/`、`files/` 下的引用附件，没有额外 manifest。

本插件复用官方 `sessionLogZipEntries` 导出内容，使用官方格式目录严格解析和验证日志，再经 `sessionPersistence.create → append → flush → close` 保存。不会直接复制持久化文件或 SQLite 索引，也不会自行重放工具进程。

当前只接受 V4 日志。不支持旧代日志、未来代日志、ZIP64、加密 ZIP 或额外文件。某些插件把附件引用保存在自定义事件中，而官方导出器没有打包这些引用；这类插件的外部数据不能据此视为已经备份。

详细来源与设计取舍见[调研记录](../../docs/research/session-migration.md)。

## 安全与恢复边界

- **档案未脱敏、未加密。** 可能包含指令、推理记录、工具参数和输出、代码片段及敏感附件，应按敏感数据保存和传输。
- **可信来源确认不是隔离机制。** 日志中的权限设置可能在继续会话后生效，包括完全访问、禁用审批和待处理消息。不要导入陌生档案。
- 仅映射日志头的工作目录。历史文本、工具参数和交付物中的旧绝对路径不会被替换；继续后须核对实际目标。
- 不包含项目目录、外部交付物、Git 私有检查点对象、运行中的进程、定时任务存储、宿主配置或登录凭据。会话恢复不等于环境恢复。
- 导出逐会话读取已提交日志，不是整棵会话树的原子快照；应先等待全部工作停止。
- 整份档案的日志、附件、谱系和目标版本在写入前校验；提交时重读目标事实。预览之后目标变化会拒绝导入，存储创建也会拒绝同 ID 的竞争写入。
- 附件保存后必须保持源引用的哈希和关键元数据。目标附件服务若重编码图片导致身份变化，导入会明确失败，不修改历史引用。
- 单份会话日志由宿主持久化服务发布；整批会话、附件及工作区关联**不是一个全局事务**。中途失败可能留下已保存会话、附件或尚未确认完整的日志，界面会报告已完成数量和不完整的 ID，不自动删除或回滚用户数据。

## 限额与失败处理

| 项目         | 上限    |
| ------------ | ------- |
| ZIP 压缩大小 | 64 MiB  |
| 总解压大小   | 256 MiB |
| 单个条目     | 64 MiB  |
| 单份日志     | 16 MiB  |
| ZIP 条目数   | 4096    |
| 会话数       | 256     |
| 单会话事件数 | 100,000 |

校验 CRC、附件 SHA-256、重复路径、重复 ID、路径与日志身份、谱系关系及格式语义。不把 ZIP 解压到文件系统；伪造声明长度的压缩内容也受实际输出限额约束。

- **预览有冲突**：保留两侧数据。当前版本不支持增量追加、重命名副本或自动合并；不要通过删除目标会话来强行绕过冲突。
- **提交后超时或连接断开**：远端可能已经保存。必须重新预览，不能把网络失败当成已回滚，也不要直接重试导入。
- **部分失败**：先保存错误详情。重新预览可识别已完整保存的会话并跳过；不完整日志可能与源内容冲突，此时停止操作并保留档案，不盲目覆盖。工作区关联失败可在日志一致时重新预览并重试关联。
- **本机导入成功但列表刷新失败**：刷新页面，检查目标工作区。

## 长期跨机器使用建议

如果机器已长期联网，优先把远端 DSH 实例作为会话的唯一写入位置：不同机器通过 dsh-remote 打开同一远端实例。这样无需复制和合并会话日志，跨机器切换的是访问入口，而不是会话所有权。

离线 ZIP 更适合备份和一次性交接。迁移后在目标继续时，应停止在来源会话中继续写入；当前版本不会把两侧后续对话自动合并。不要用文件同步软件同步正在使用的整个 DSH 数据目录或可写 SQLite 文件。

## 开发验证

```bash
pnpm --filter @weilence/dsh-sessions typecheck
pnpm --filter @weilence/dsh-sessions test
pnpm --filter @weilence/dsh-sessions build
```

测试覆盖官方 ZIP 往返、严格格式和附件校验、谱系、并发冲突、部分完成结果、路由认证、远端协议接线和中英文界面。真实跨机器 SSH 与当前桌面 GUI 仍需部署后验收。
