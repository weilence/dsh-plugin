# @weilence/dsh-sessions

在 DSH 的「设置 → 会话」页面中，点击「导入会话」，在弹窗内选择目标工作区和一个或多个宿主导出的 ZIP，即可导入完整日志、子会话及引用附件。页面下方可搜索并恢复已归档会话。插件配置页和侧栏不再提供重复入口；导出继续使用宿主右上角的下载会话功能。

只创建目标上不存在的会话，内容完全相同则跳过。同一 ID 的内容不同就拒绝导入，不覆盖，也不合并分叉历史。

## 安装与启用

需要 DSH `0.2.0-rc.2` 的会话、附件、工作区及 Web 连接服务。此版本在本仓开发，尚未因本次开发自动发布到 npm。

```bash
pnpm install
pnpm --filter @weilence/dsh-sessions build
# 将路径替换为本机实际插件目录，profile 替换为正在使用的 profile。
dsh plugin --profile <profile> add /absolute/path/dsh-plugins/plugins/dsh-sessions
```

安装或更新后重启宿主，并刷新页面。宿主侧的路由变更不能仅靠刷新浏览器生效。

## 导入会话

1. 在来源机器上等待主会话及子会话停止运行，再使用宿主自带的下载功能导出 ZIP。
2. 在目标实例中打开「设置 → 会话」，点击「导入会话」。
3. 选择目标工作区和一个或多个 ZIP。没有工作区时，先在左侧列表中添加；导入不会猜测目标或默认沿用来源机器的目录。
4. 确认 ZIP 来源可信，点击「导入会话」。插件逐份校验并导入；某份失败后继续处理其他 ZIP，各文件的结果和实际错误显示在底部按钮旁。
5. 成功的普通会话关联到所选工作区。完成后会请求刷新会话列表；列表未更新时请刷新页面。导入不会自动打开或运行会话；检查目标环境和历史权限后，再打开会话继续。

设置页的导入入口只有一个按钮，工作区和 ZIP 均在弹窗中选择，不需要手动预览或填写目录。导入时自动读取目标版本，写入前再次核对；目标发生变化时拒绝写入，不盲目覆盖。

目标上同 ID 的会话必须未加载到内存；已打开或正在运行的会话会被拒绝。若需要重启目标宿主释放会话，请先妥善结束目标上的其他工作。子会话保留其身份及父子关系，不会改成普通主会话；能否继续执行取决于宿主的子会话恢复契约。

跨机器导入时，将 ZIP 复制到目标机器后，在目标 DSH 页面执行上述操作。本插件不提供在线远端传输面板。

## 恢复已归档会话

1. 打开「设置 → 会话」，在「已归档会话」中按标题、路径或会话 ID 搜索。
2. 点击对应条目的「恢复」。操作期间防止重复提交；失败时，实际错误显示在该按钮旁，可检查原因后重试。
3. 成功后，宿主的归档状态会更新，该条目从归档列表中移除。现有会话重新显示在宿主的常规列表中，不自动打开，也不改变其工作区归属。

归档不是删除或 ZIP 备份。此页面只展示当前连接的 DSH 实例中的归档；连接远端时，操作的是远端实例。加载或连接失败时不将旧列表当作当前状态，恢复按钮禁用并显示原因。

归档 ID 以宿主工作区服务为准，会话摘要只用于展示标题、路径和更新时间。摘要尚未加载或当前列表暂无信息时，仍显示归档 ID；恢复仅通过官方接口取消归档，不重建已被删除的日志或附件。第一版不提供批量恢复、删除或远端传输。

## 格式与安全边界

- 接受宿主官方 ZIP：根日志、后代会话日志及引用附件，没有额外 manifest。当前只支持 V4，不支持旧代或未来代日志、ZIP64、加密 ZIP 或额外文件。
- 使用官方格式目录严格解析和验证日志，再经 `sessionPersistence.create → append → flush → close` 保存。不直接复制持久化文件或 SQLite 索引，不重放工具进程。
- 宿主按目标平台校验日志头的原工作目录。跨操作系统的路径格式可能被拒绝，例如 Windows 路径导入 macOS；本插件不会绕过官方校验。
- **ZIP 未脱敏、未加密。** 可能包含指令、推理记录、工具参数和输出、代码片段及敏感附件，应按敏感数据保存和传输。
- **点击导入表示确认来源可信，不是隔离机制。** 继续会话后，日志中的权限设置可能生效，包括完全访问、禁用审批和待处理消息。不要导入陌生档案。
- 仅映射日志头的工作目录。历史文本、工具参数和交付物中的旧绝对路径不会被替换；继续后须核对实际目标。
- 不包含项目目录、外部交付物、Git 私有检查点对象、运行中的进程、定时任务存储、宿主配置或登录凭据。会话恢复不等于环境恢复。
- 宿主导出逐会话读取已提交日志，不是整棵会话树的原子快照；应先等待全部工作停止。自定义事件中未被官方导出器打包的附件或插件外部数据，不能据此视为已经备份。
- 整份 ZIP 的日志、附件、谱系和目标版本在写入前校验。存储创建也会拒绝同 ID 的竞争写入。
- 附件保存后必须保持源引用的哈希和关键元数据。目标附件服务若重编码图片导致身份变化，导入会明确失败，不修改历史引用。
- 单份日志由宿主持久化服务发布；整批会话、附件及工作区关联**不是一个全局事务**。中途失败可能留下已保存会话、附件或尚未确认完整的日志。界面报告已完成数量和不完整的 ID，不自动删除或回滚用户数据。

## 限额与失败处理

| 项目         | 每份 ZIP 的上限 |
| ------------ | --------------- |
| ZIP 压缩大小 | 64 MiB          |
| 总解压大小   | 256 MiB         |
| 单个条目     | 64 MiB          |
| 单份日志     | 16 MiB          |
| ZIP 条目数   | 4096            |
| 会话数       | 256             |
| 单会话事件数 | 100,000         |

校验 CRC、附件 SHA-256、重复路径、重复 ID、路径与日志身份、谱系关系及格式语义。不把 ZIP 解压到文件系统；伪造声明长度的压缩内容也受实际输出限额约束。

- **内容冲突**：保留两侧数据。当前版本不支持增量追加、重命名副本或自动合并；不要删除目标会话来强行绕过冲突。
- **超时或连接断开**：宿主可能已经保存。先刷新页面检查结果，不能把网络失败当成已回滚。重新导入会自动比对目标数据。
- **部分失败**：先保存错误详情。重新导入可识别已完整保存的会话并跳过；不完整日志可能与源内容冲突，此时停止操作并保留 ZIP，不盲目覆盖。工作区关联失败可在日志一致时重试关联。
- **导入后列表刷新失败**：刷新页面，检查目标工作区。

离线 ZIP 适合备份和一次性交接。迁移后在目标继续时，应停止在来源会话中继续写入；当前版本不会把两侧后续对话自动合并。不要用文件同步软件同步正在使用的整个 DSH 数据目录或可写 SQLite 文件。

```bash
pnpm --filter @weilence/dsh-sessions typecheck
pnpm --filter @weilence/dsh-sessions test
pnpm --filter @weilence/dsh-sessions build
```

测试覆盖宿主 ZIP 兼容性、严格格式和附件校验、谱系、并发冲突、部分完成结果、路由认证、多个文件的串行导入，以及设置入口、弹窗、归档搜索、串行恢复、状态变化和中英文反馈。实际 GUI 仍需部署后验收。
