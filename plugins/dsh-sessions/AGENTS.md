# dsh-sessions

侧栏会话行「…」菜单插件：跨工作区迁移与迁移 Agent 预设，弹窗统一挂在 `shell.overlay`。

理解本插件的前提：菜单条目只发起弹窗请求，弹窗本体挂在行外的常驻宿主（行随菜单关闭卸载）；数据事实全部来自官方客户端快照；而迁移 / 预设迁移绕过宿主官方接口、直接对官方 JSONL 持久化工件做磁盘手术——这是官方契约外的受控操作，宿主不感知这类改动，数据安全完全由本插件自带的闸门、互斥与回滚保证。

## 强制约定

- 活会话一律拒绝（`guards.ts` 的 `assertNotLoaded`）：绕过活内存态改写会让宿主追加路径重建部分日志。host 进程的 `ctx.sessions` 是官方 `SessionStore`；它与客户端 `ISessions` 经同名 Context 声明合并相遇，类型面必须显式取用宿主侧类型（`Pick<SessionStore, 'get'>` 断言），不得依赖声明合并进入程序的顺序。
- 一切工件改写走 `writeTempFile`（0o600 + fsync）+ 备份-发布-回滚三段式；回滚失败保留备份并上报路径。
- 损坏工件（截断帧 / 不完整尾行）与同 id 多目录一律拒绝改写，绝不猜测修补。
- 磁盘迁移发布顺序固定「先隐藏旧工件（非规范文件名对官方后端不可见）再发布新工件」，宁可短暂缺失也不产生同 id 双目录。
- 迁移 / 预设路由共用同一全局存储互斥（`src/index.ts` 的 `exclusive`），新增变更路由必须接入。
- 菜单条目只发起请求不持有弹窗：迁移 / 预设弹窗统一由 `shell.overlay` 常驻条目分发（`src/client/dialogs.tsx`）；两弹窗自带反馈（Toast），无需额外通知通道。
