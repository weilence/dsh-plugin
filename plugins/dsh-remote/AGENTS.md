# dsh-remote

设置页「远程开发」插件，包名 `@weilence/dsh-remote`（无 scope 的包名 `dsh-remote` 在 npm 已被第三方包占用——远端安装因此不走 registry，见部署约定）：经 OpenSSH 管理远端机上的完整 dsh web 实例（连接（内含远端部署，即原独立的「部署」操作）），并提供环境同步能力（skills / MCP / 插件 / 系统提示词）及 dsh-sessions 使用的已连接远端传输通道——dsh-skills / dsh-mcp / dsh-prompts 保持纯本地管理插件、不感知远端。连接有三种登录方式：**SSH 别名**（认证完全交给 `~/.ssh/config`，该别名须已能免交互登录，本插件不为它补密码）、**密码**、**密钥文件**（可带私钥口令）。**没有「断开」操作**：本地转发随宿主退出（dispose）或意外中断（onExit → error）消失，远端实例是 systemd 用户服务（enable-linger 常驻 + 开机自启 + 崩溃自动拉起），下次连接按单元复用秒连（版本不符时自动 systemctl restart 收敛，见引擎段）。

## 结构

- `src/index.ts`：host half，十一个 HTTP 路由（state / local-rows / remote-inventory / save / delete / test / connect / version / sync / ssh-hosts / secret）；`applyWithEngine` 是测试注入口；生产 ssh 面由 `createSshTransport(dshHomePath())` 提供（exec / 转发 / tar 共用同一套目标参数与环境）。部署在本机侧的准备动作也在此接线（`localDshVersion` / `localPluginVersion` / `packPlugin` / `packPackage` 经 `pnpm pack` 打包（发布语义：files 白名单 + prepack 构建 + catalog:/workspace: 依赖落成具体 range；产物名 `<扁平化包名>-<version>-<tgz sha256 前 8 位>.tgz`——内容盐使同版本换内容的强制重推换 specifier，hoisted linker 才会真正重新解包；宿主进程找不到 pnpm 显式报错）/ `pushFile` 把 tgz 二进制经 ssh stdin 落盘）。`GET /version` 上报实例运行身份（dsh + 插件版本，**模块加载时定格的快照**——连接判定的比对目标，也是远端实例上同一份代码的自报通道；`instanceVersion` 依赖经隧道 token 换 Cookie 后请求，复用 `transport.ts` 的 `exchangeTunnelCookie`）。`POST /test` 是表单里的**无状态探针**（`{id?, target, secret?}`，不占连接操作位、不改阶段）；`GET /ssh-hosts` 只读扫描 `~/.ssh/config`（选择器）；`POST /secret` 把现场补录的口令只放进宿主内存。
- `src/engine.ts`：连接状态机（阶段 + 进行中操作 + running 事实）与全部操作流程（连接 = 部署段各步骤 + systemd 单元落盘/启动轮询 + **实例版本判定**：单元 active 且内容未变即复用候选，隧道上问 `/version` 与本机比对——不匹配（本机已升级 / 旧插件 404）或复用实例无响应时 `stopInstance`（systemctl stop）收敛一轮回环，重启后仍不匹配按原样报错；三类同步 = 弹窗远端事实判定出徽标 + 提交即执行（勾选已一致项即强制重推）；删除连接 = 本地全清（转发 + 租约 + 记录 + 会话口令，运行中可删），远端实例不动）；`beginOp` 同步抢占互斥锁，长操作 fire-and-forget，面板轮询 GET /state 跟踪。口令：`secretOf` = 落盘口令优先、其次本次运行的会话口令表（`sessionSecrets`，`rememberSecret=false` 时的唯一落点）；密码登录没有可用口令时 `beginOp` / `remoteInventory` 抛 `SecretRequiredError`（路由 409，面板据此弹补录框），不把注定失败的认证算成连接失败；`probe(request)` 是无状态表单探针（不占互斥锁、不改阶段、不要求先保存）。
- `src/service.ts`：systemd 托管装配层——单元名固定 `dsh-web.service`（一台机器一个实例，不随连接 id / 包名变化；日志路径同样固定 `~/.dsh/dsh-remote/web.log`）、单元内容（Type=exec + 登录 PATH 整体注入 + ExecStartPre 截断日志 + append 输出到既有日志路径 + `Restart=on-failure`/`TimeoutStopSec=15s`）与启动 / 停止 / 轮询三条远端命令的确定性构建（单测直接断言文本）；失败经标记行（`__NOSYSTEMD__` / `__LINGERFAIL__` / `__NOBUS__` / `__STARTFAIL__` / `__STOPFAIL__`）分类报错，**无 nohup 回退**。
- `src/ssh.ts`：ssh 执行器（node:child_process 直接 spawn + 错误分类）、`bash -lc` 登录 shell 包装（npm 全局 bin 进 PATH）、tar-over-ssh 单通道、`ssh -N -L` 转发句柄，以及**连接目标 → ssh 参数 / 环境**的组装（`buildSshInvocation`，参数矩阵见下）与**口令通道**（`createAskpass`：`<DSH_HOME>/dsh-remote/askpass.cjs` 经 `NODE_OPTIONS=--require` 预载、宿主可执行文件作 `SSH_ASKPASS`，首次使用写 hook + 自检）。**刻意不做 ControlMaster 连接复用**：宿主环境实测连接 poll 的长会话两次挂死（就绪行早已写入日志、slave 等不到数据直到本地超时；加 ServerAliveInterval 保活也未能幸免），同形态独立复现（裸 ssh / node spawn / mux 全组合、新启动静默等待 124s 命中）均未重现——宿主进程环境的差异不可穷尽，按确定性优先移除；建连开销由批量执行路径消化（部署段探查九合一 + poll 远端有界循环 + verify/pid 附带，必经连接 ~9 次 → 3 次，全平台统一）。
- `src/sshconfig.ts`：`~/.ssh/config` 的只读扫描（`readSshConfig`：`Host` 段取首值语义、通配 / 否定段跳过、`Match` 截断、`Include` 就地展开（`~` / `${ENV}` / glob / 深度与环检测））——只供选择器展示「配置里声明的」hostname / user / port / 密钥 / 跳板；**连接参数永远由 ssh 自己解析配置**，这里不模拟 `Match` 与默认值继承（摘要常缺 `Host *` 的 User / Port，属展示层近似）。
- `src/transport.ts`：复用唯一引擎注册 `ctx.remoteTransport`，只公开连接清单及会话预览 / 导入两条 POST；共享契约在 `@dsh-plugins/shared/remote`。每次请求经已连接隧道的启动 token 换取 authority 绑定 Cookie，接收路由仍须宿主认证与 `x-dsh-sessions` 标记；不持久化 Cookie、不跟随跳转，连接变化或提交结果不明时要求重新预览。会话档案与面板由 dsh-sessions 管理。
- `src/launch.ts`：远端启动行 `dsh web: <url>` 的宽松解析（端口 + token；格式无版本契约）。
- `src/patchDoc.ts`：本机两层 patch 的层扫描（insert 行读取），供插件同步清单；MCP 同步已迁往 .mcp.json 合并，不再写 patch。
- `src/localenv.ts`：本机清单只读扫描（skills 两根扫描（含 `foldSkillDigest` 内容指纹折叠——远端 find|sha256 输出共用同一折叠）、全局 mcp.json 条目扫描（`readLocalMcp`，条目对象规范化 JSON 签名）与插件行——插件行 = patch insert 行 ∪ 层 package.json `dsh.profile.bundles` 激活清单（link 安装的主要登记处，`@deepseek-ai/*` 平台包过滤）；行含安装形态与包定位：dependencies 的 link:/file: spec 为本地、spec 目标即包根；registry 行定位到层内 node_modules 实体；行带本机包版本（同步插件的比对判据）；系统提示词行 `scanSystemPrompt`（profileContext.home 下的 system-prompt.md，与 dsh-prompts 同一文件））——全部只读。
- `src/connections.ts`：`$DSH_HOME/dsh-remote.json`（v2）持久化（连接库 + 同步 manifest）与保存请求校验。连接目标是判别联合：`alias`（认证交给 `~/.ssh/config`）或 `direct`（host / port / user / auth=key|password / identityFile）。落盘形态 `StoredConnection` 多一个 `secret` 与 `rememberSecret`：只有勾选「记住」才写盘，否则口令只进引擎内存；`RemoteConnection` 只暴露 `secretState`（saved / session / none），**口令值永不出 host**。v1 的 `{sshAlias}` 记录读入即迁移为别名目标；id 缺省从别名或 host 派生；写盘 0600 + tmp/rename。
- `src/forwards.ts`：本地转发租约（`$DSH_HOME/dsh-remote/forwards.json`）——连接成功落盘 `{pid, localPort, remotePort, at}`，删除连接 / 转发死亡清除，引擎 load 时清扫上个宿主生命周期遗留（`ssh.ts` 的 `killOrphanForward` 核验命令行后才杀）；短命记录、损坏即弃，不参与任何连接判定。
- `src/client/`：面板；连接为可展开卡片（进行中与失败态文字进度 pill 让位——op 进行中是 spinner（官方 StateDot ongoing，占按钮区最左位与动作按钮中心对齐，hover 经 OpHoverCard 浮层展示 progress 步骤时间线：官方 MenuSurface 材质 + useAnchoredPosition + body portal，z-index 1100 高于设置弹窗的 1000——官方 HoverCard 的卡片 z-100 在弹窗下不可见故弃用；移出后 250ms grace 供指针移入面板）、error 阶段是「连接失败」入口（按 progress.kind 取词：连接 / 同步失败，点击开 Dialog：错误摘要 + 步骤时间线 + detail 全文）；其余阶段显示阶段 pill + 动作按钮按阶段渲染——运行中只有「打开」（**连接成功不自动开页**，store 的阶段迁移检测发 toast；无断开操作，转发随宿主退出或意外中断消失），非运行中只有「连接」；「删除」运行中也可用（本地全清，远端实例保留），行上带同步下拉（hover 展开四项菜单））。**测试按钮在新增 / 编辑表单里**（卡片上没有）：不保存、不要求名称、只校验目标字段，结果只走一次性 toast（`noticeSeq` 作 Toast 的 key，同文案也重新计时），失败摘要需全文时看「连接」的失败详情弹窗。表单三段登录方式（`SegmentedControl`：SSH 别名 / 密码 / 密钥文件）+ 按段显示的地址 / 端口 / 用户 / 密钥路径 / 口令（官方 `SettingsSecretField` 写-only，已配置状态 + 留空不改 + 「清除已保存的口令」）+ 「记住口令」勾选（默认不勾）+ 别名选择弹窗（`SearchBox` 过滤，行内别名可点、元信息与路径保持文本可选）；菜单选类别后 SyncDialog 打开该类清单（远端事实逐条判定出徽标：same 是行尾 ok 徽标、醒目于普通元信息，其余三态是状态文字；非 same 默认不勾选，same 项同样默认不勾、可自由勾选——勾选即强制重推；清单工具行左侧「全选」勾选框只作用当前可见行，右侧「隐藏已一致」是官方 Switch（默认开、只影响显示不改变提交集）），确认即随 POST /sync 直接提交勾选项（无中间保存；同步完成 / 失败由 store 的 op 迁移检测发 toast 摘要；同步失败而连接仍在 running 时错误摘要行 + 「查看完整」机制保留）；HTTP 封装自定义头 `x-dsh-remote`。**口令弹窗**：密码登录的连接没有可用口令时（典型：没勾「记住」而宿主重启过），点「连接」或同步菜单先弹 Dialog 现场补录（`POST /secret` 只进内存，补完继续原动作）。全部展示文案跟随宿主语言：slot 注册声明 `locale: NS`，组件的 `t` 由框架标准 seat 合成进 props（窄类型 `RemoteT`），取消 / 关闭 / 删除 / 保存用 common 词条；`ConfirmDialog` / `Dialog` 的 `cancelLabel` / `closeLabel` 由调用方传入，不内嵌文案。
- `src/client/locales.ts`：本插件词典（命名空间 `dsh-remote`，zh 为键集事实源、en 编译期查全），client `apply` 经 `ctx.effect(() => ctx.locale.register(...))` 注册，slot 注册声明 `locale: NS` 后组件的 `t` 由框架标准 seat 合成进 props（apply 域 `bind` 只服务导航 label thunk；label 必须 thunk——注册时取词会定格）；`PanelMessage`（`{key, params}` 或 `{text}`）是 store / 弹窗投影的消息描述子（连接成功与同步摘要等跨语言切换存活的 toast 整句入词典，不把可译片段当参数拼接），渲染期经 `messageText` 取词——Host errMsg / ssh 输出 / 条目名等外部事实用 text 原样展示，不翻译不吞。单测取词用 `test/i18n.ts` 的 `makeT`（含 common 词条快照）。

## 改动约定

- 远端 profile 固定 `web`（`REMOTE_PROFILE` 常量；面板无输入、wire 无字段。shipped web 模板含 dsh-web-app——`--no-open`/`--port 0` 是它的 flag、`dsh web:` token 行由它输出；headless 模板是一次性 agent，两者缺一则连接不成立）；远端 dsh 版本在连接的部署段对齐本机运行时（host 侧运行时 import `@deepseek-ai/dsh-app-boot` 取 `getDshRuntimeVersion()`，**探测失败直接中止部署——禁止回退安装 npm latest**）。
- 四类同步一律手动触发（下拉菜单选类别 → 弹窗勾选 → 确认），连接过程不执行任何同步动作；同步入口在所有阶段常驻——skills / MCP / 提示词仅需 ssh 可达，插件安装依赖连接部署出的远端 dsh，未连接时点「同步插件」先弹出「连接远端」引导弹窗（确认后立即关闭弹窗并发起连接，连接进度由卡片 spinner（hover 看过程）呈现，连接完成后由用户重新点一次菜单）；同步语义 = **只往远端新增/覆盖，永不删除远端内容**——勾选 = 安装/覆盖，未勾选 = 不动，远端独有条目（本机没有的）不受影响；要清理远端用远端实例自己的 dsh-skills / dsh-mcp 面板。勾选项随 POST /sync 直接提交（`{id, kind, names, registryPluginInstall?}`）——不持久化在连接上、无中间保存步骤（历史上的"先 save 后 sync"两步协议、`connection.sync` 字段与 `kind=all` 已删除，"未勾选=删除"的声明式语义也已删除）。条目级「一致」判定双端同函数（shared.ts 的 `skillStatus` / `mcpStatus` / `pluginStatus` / `promptStatus`，弹窗徽标用）：skills 比内容指纹（本机 walk 与远端 `find|sha256` 管线共用 `localenv.foldSkillDigest` 折叠；隐藏路径段两侧同样跳过，目录包与 `<name>.md` 单文件取并集；刻意不比 mtime/mode）、MCP 比生效配置签名（`canonicalJson` 递归键序无关，disabled 入签）、插件比「bundles 激活 + 版本号」（npm 语义：版本即内容契约，本地打包传输与远端 npm 下载同判；远端一条 `node -e` 批量读版本；同版本换内容不可见，改码推远端 bump version 或对已一致项强制重推）、提示词比单文件内容 sha256（本机 `scanSystemPrompt`，远端 sha256sum/shasum 单文件管线，文件缺失打 `__ABSENT__` 哨兵；推送走 tmp+mv 原子写远端 `~/.dsh/system-prompt.md`）；比对值任一侧读不到时按「无法比对」展示。弹窗打开时 POST remote-inventory 取远端事实逐条判定：非 same 项默认不勾选（打开看到的是待决策清单），same 项也默认不勾、可勾选——**勾选已一致项 = 强制重推**；「隐藏已一致」Switch 只影响显示，「全选」只作用当前可见行。**引擎提交即执行、不重读远端事实重判**（弹窗判定就是事实源）：勾选项全量推送 / 写入 / 安装，无「一致跳过」分支，lastSync 只报处理量；未勾选与远端独有条目不受影响。插件分流：本地路径安装恒本地打包传输（未发布的开发版本也能到达远端），registry 插件按请求选项 `registryPluginInstall` 选「本地传输」或「远端 npm 下载（add name@本机version）」；package.json 的 `file:` spec 持续引用当前 tgz（pnpm 后续任何 add/install 都会重读全部 file: 依赖），装成功后只清同包**其他版本**的 payload 文件，当前文件必须保留；manifest（`dsh-remote.json` 内）只是最近一次同步的记录，不驱动任何判定。提示词同步与 dsh-prompts 面板管理同一文件（系统提示词 `~/.dsh/system-prompt.md`，远端需装 dsh-prompts 才注册进系统提示词组装）；dsh-prompts 配置单独覆写 dshHome 时本插件读不到该覆写（插件配置宿主不公开）。
- 远端装本插件不走 registry（无 scope 包名被第三方占用）：连接的部署段对比远端 `node_modules/@weilence/dsh-remote` 的 version 与 profile 登记及本机版本，全部一致则跳过；否则 `packPlugin` 经 `pnpm pack` 打 tgz（prepack 即 tsdown，产物现建）→ `pushFile` 落盘 `~/.dsh/dsh-remote/payload/` → `dsh plugin add "$HOME/....tgz"`；安装完成后读回远端 package.json 的 version 防假阳性（add 退出码 0 不代表安装成功——旧实现只查 `dsh -V`，实测掩盖过未安装的情况）。
- 插件激活写远端 profile package.json 的 `dsh.profile.bundles`（不是 patch 行）；同步 MCP 合并写远端 `~/.dsh/mcp.json`（条目名即 serverName：只新增/覆盖，远端独有条目与顶层其他键不动，Map 原位覆盖保键序）；工作区档（`<cwd>/.mcp.json`）是目录特定，不参与跨机同步；远端 dsh-mcp 面板可无缝接手。
- 本插件不做第二套远端状态存储：连接库持久化在 `$DSH_HOME/dsh-remote.json`；运行态（阶段 / 转发子进程 / pid）只驻内存，宿主重启即回到 idle——唯一例外是本地转发租约（`src/forwards.ts`，`$DSH_HOME/dsh-remote/forwards.json`）：它不驱动任何判定，只让引擎 load 时能杀掉上个宿主生命周期遗留的 `ssh -N -L` 进程（宿主被 SIGKILL / 崩溃不走 dispose 兜底），使「重启即 idle」不带幽灵隧道。
- ssh / tar / pnpm 经 node:child_process 直接 spawn（pnpm 在 Windows 是 .cmd，走 shell 并给路径加引号）。**认证参数矩阵**（`buildSshInvocation`）：别名 = `BatchMode=yes` + 原样别名；密钥无口令 = `-i <file> -o IdentitiesOnly=yes -o PreferredAuthentications=publickey -o BatchMode=yes`；密钥有口令 = 同上去掉 BatchMode、加 `NumberOfPasswordPrompts=1` 与口令通道；密码 = `-o PubkeyAuthentication=no -o PreferredAuthentications=password,keyboard-interactive -o NumberOfPasswordPrompts=1` + 口令通道。直连统一 `StrictHostKeyChecking=accept-new`（未知主机自动记录，变更时硬失败），目标前一律加 `--` 终止选项。口令通道 = `SSH_ASKPASS_REQUIRE=force` + `SSH_ASKPASS=<宿主可执行文件>` + `ELECTRON_RUN_AS_NODE=1` + `NODE_OPTIONS=--require "<hook>"` + 口令环境变量；hook 首次使用时写盘（0600）并自检。
- 三种登录方式的口径：**别名不补密码**——`BatchMode=yes` 下 ssh 不会提问，认证失败文案给出「配密钥 / 改用密码或密钥文件」两条出路；别名也不接受面板口令（`/secret` 直接 400）。密码与私钥口令共用同一个 `secret` 槽，但**认证方式切换且未重填口令时不沿用旧值**（私钥口令与登录密码不是一回事）。密码连接允许没有口令（用户点了「清除已保存的口令」）：保存放行，操作前由引擎抛 `SecretRequiredError` 走补录弹窗。
- 远端实例由 systemd 用户服务托管（`src/service.ts` 装配，engine 执行）：每次连接幂等落地单元 `~/.config/systemd/user/dsh-web.service`（内容经 cmp 比对，一致不重写；变化 mv + daemon-reload + restart 生效）→ `loginctl enable-linger` 并验证（常驻与开机自启的前提，每次连接重试自愈管理员关闭 linger 的情况）→ 单元未变且 active 即复用，否则 reset-failed + restart。**不满足 systemd（systemctl/loginctl 缺失）、用户总线不可达、linger 开不了任一条件即显式报错，不做 nohup 回退**。单元以探查到的 dsh 绝对路径启动、登录 PATH 整体注入（用户管理器默认 PATH 极简，nvm node 与 MCP server 的 uv/npx 全靠它）；`Type=exec`（要求 systemd ≥ 240）让 start 在 exec 成功后才返回，MainPID 无竞态；日志仍 append 到 `~/.dsh/dsh-remote/web.log`，就绪行解析与失败日志尾部读取不变。**单元名与日志路径都不含连接 id**：同一台机器换别名连必须命中同一个单元、同一份日志（内容不变 → cmp 命中 → 不重写不 restart），把 id 或插件包名写进单元名会分裂成两个实例、并让连接互相 restart；`<id>.pid` 只作为旧 nohup 形态的迁移清理路径保留。
- 远端写操作四处固定：`~/.dsh/dsh-remote/`、`~/.config/systemd/user/`（实例单元）、`~/.dsh/profiles/<name>/`、两个 skills 根；一律 tmp+mv 原子落盘或幂等命令。
- `dsh web:` 启动行解析保持宽松（前缀 + 首个 URL + token query），不假设路径形态。
- 远端清单读取（remoteInventory：skills 两根 `find . -type f ! -path '*/.*' | xargs -0 sha256sum`（sha256sum / shasum 择一，hasher 缺失时打 `__DSH_NO_HASHER__` 哨兵）、MCP 全局档条目按名取签名（结构坏该类 null）、插件取 bundles + `node -e` 批量读版本、提示词单文件 sha256（缺失打 `__ABSENT__`））解析失败按该类 null 降级——弹窗按「无法比对」徽标渲染但**不阻断同步**（只新增/覆盖无删除风险，最坏是无对比的全量覆盖勾选项）；ssh 连接级失败原样抛。

## 陷阱

- **口令场景不能设 `BatchMode=yes`**：它是「终端前没有人」开关——password / keyboard-interactive 认证方法被整条跳过，加密私钥的加载循环在空口令试解失败后直接 `quit`（见 `sshconnect2.c` 的 `load_identity_file`），**根本不会进入 `read_passphrase`，askpass 也就不会被调用**。所以有口令可递时必须去掉 BatchMode，靠 `PreferredAuthentications` + `NumberOfPasswordPrompts=1` 保证只走预期认证并只重试一次；没有口令可递时反而要用 BatchMode 防止 ssh 等一个永远不存在的终端。
- Windows 的 `CreateProcess` **不能把 `.cmd` / 脚本当 `SSH_ASKPASS`**（实测 `spawn` 直接 EINVAL）——Win32-OpenSSH 用 `posix_spawnp` 起 askpass，只认可执行映像。因此 hook 走 `NODE_OPTIONS=--require`：`SSH_ASKPASS` 指向宿主自身可执行文件，Electron 宿主需 `ELECTRON_RUN_AS_NODE=1` 才会以 Node 模式运行；hook 读到环境变量后立刻写 stdout 并 `process.exit(0)`（不 exit 的话 Node 会把 ssh 传来的提示词当成入口脚本解析而报错）。NODE_OPTIONS 里的 hook 路径用正斜杠并加双引号（路径可能含空格；反斜杠会被 NODE_OPTIONS 解析器当转义吃掉）。首次使用做一次自检，机制失效时给出明确错误而不是让 ssh 报含混的 Permission denied。
- 别名连接**没有**口令入口是刻意的：给别名塞密码会覆盖配置里的认证顺序，且 `ProxyJump` 的口令提示会拿到同一份口令（跳板机与目标机口令可能不同），失败原因极难排查。需要密码时用「密码」方式新建连接，或把密钥配进 `~/.ssh/config`。
- 口令只允许出现在三处：勾选「记住」时的 `dsh-remote.json`（0600）、引擎的会话口令表、ssh 子进程环境。`/state`、保存响应、进度步骤、错误详情、日志里都不得出现明文；`RemoteConnection` 只有 `secretState` 三态（saved / session / none），`toRemoteConnection` 必须整字段投影而不是展开 `StoredConnection`。
- `ssh` 的命令级失败摘要必须走 `summarizeOutput`（cleanLines 会剔除本机 ssh 客户端横幅）；直接 `stderr.trim()` 会让 OpenSSH 10 的 post-quantum 警告顶掉真实原因（已在 `classifySshFailure` 修正）。
- 本机 dsh 版本探测必须经运行时 import `@deepseek-ai/dsh-app-boot`（peer 声明保持外置，动态 import + catch 软失败）：宿主把平台包经运行时解析供给插件，静态 node_modules 目录探测在宿主形态下落空。探测失败时**禁止回退安装 npm latest**——latest 标签可能落后于 next（实测 latest=0.1.7-rc.2、0.2 线在 next），装出旧 dsh 后 `dsh plugin add` 会被 engines 版本检查拒绝（allow-version 提示即此），宁可中止部署。
- 返回空库的分支必须用字面量新建对象，不得展开共享默认值——浅拷贝会共享 `connections` 数组引用，一次 push 污染所有读到空库的调用方（已修过一次，勿再引入）。
- 远端命令统一 `bash -lc` 包装：非交互 ssh 不读用户 profile，nvm 装的 node / npm 全局 bin 可能不在 PATH 中。
- `dsh plugin` 的 `--profile` 必须在子命令前（Commander requiredOption 先于 variadic args）。
- 本机（及插件同步清单）对「本插件自身」的排除要同时匹配 `@weilence/dsh-remote` 与改名前的无 scope 包名 `dsh-remote`——本机 link 安装在改名重装前的过渡期仍保留旧名行，漏排会把自身当业务插件同步出去。
- `SshExecOptions.stdin` 是 `string | Uint8Array`：tgz 走二进制原始字节，ssh 通道本身二进制安全。
- 插件打包只走 `pnpm pack`，禁止回退自拼 tar：catalog:/workspace: 依赖 spec 由它落成具体 range——自拼 tar 会把字面 `catalog:` 带进 tgz，远端 pnpm 解析不了（`ERR_PNPM_SPEC_NOT_SUPPORTED_BY_ANY_RESOLVER`，实际发生过）。`--json` 输出会被 prepack 脚本的 stdout 污染，产物名不解析输出，改为读全新空目录里唯一落地的 tgz。宿主进程解析不到 pnpm 时显式报错（GUI 启动不继承 shell rc 的 PATH），不静默换实现——两套打包行为会让产物不确定。
- 远端 profile 的 `pnpm-workspace.yaml` 固定 `nodeLinker: hoisted`：其下 `pnpm add` 的更新判定只看 specifier（dependencies 里的 spec 字符串），**不校验 tgz 字节变化**——同 name@version 换内容不会重新解包，`--force` 也绕不过（实测 pnpm 11.7.0）。payload 文件名带 tgz 字节的内容盐（`<扁平化包名>-<version>-<sha256 前 8 位>.tgz`）：版本变或内容变都换 specifier、必重新解包；内容真一致则同名、远端自然跳过。插件的判等仍以版本为锚——同版本换内容不会被判为 diff，改码推远端走 bump version 或对已一致项强制重推，与自部署段、实例 `/version` 判定同一语义。
- payload 目录的 tgz 不是纯传输介质：`pnpm add <tgz>` 把 `file:<tgz>` 写进 dependencies 后**长期引用**，后续任何 add/install 都会重读全部 file: 依赖——装完就删会让依赖悬空，下一个无关插件的 add 以 `[ENOENT]` + 退出码 254 失败（实际发生过：清理删了刚装的 tgz）。清理只能删同包其他版本的文件（版本段锚定数字，不误删相似名包）。另注意 pnpm 的真实错误常打在 stdout，失败详情须合并两路输出，并剔除本机 ssh 客户端横幅（OpenSSH 10 对无 post-quantum KEX 服务端打 `** … **` 提示）对 stderr 的污染。
- 同步的比对值在任一侧读不到（本机包定位失败 / 远端管道失败 / 远端 mcp.json 结构错误）时保守按不同处理——tgz 推送与 patch 写入幂等，宁可重推不可漏装。远端哈希管线按 `hash  path` 行解析（sha256sum / shasum 同形态），路径含换行等畸形文件名会解析失败、走保守分支——官方发现层（ls -1）同样受限。
- MCP 合并遇远端 mcp.json 结构坏（解析失败）时显式中止，不盲覆盖——盲覆盖会毁掉手写的其余条目；条目级签名（canonicalJson 全条目）使 disabled 与未知键的变化都判为 diff。
- 连接轮询整体在远端有界循环里（`for i in $(seq 1 150)` + sleep 2，一次建连等到就绪或 300s 耗尽——**窗口必须覆盖完整冷启动**：MCP server 串行启动且各自现场下载依赖，npm / uv 各约 2 分钟，实测两个 MCP ≈ 4 分钟，旧值 180s 让必走冷启动的路径（版本不符杀旧重启、实例崩溃后重连）必然超时；Windows 无连接复用时原先每 2s 一条 grep 意味着最多 150 次建连）；本地兜底超时 = 循环上限 + 建连余量，就算本地提前断开，远端循环有界自灭不泄漏进程。部署段九项只读事实（node/npm/pnpm/dsh 版本、插件 package.json、profile 登记、HOME / dsh 路径 / 登录 PATH 三项服务事实）同理经一条标记行命令（`__KEY__<值>` 单行协议，多行 JSON 由 `tr` 压平）一次拿全——探查彼此无依赖，合并对全平台生效（Windows 省建连、macOS/Linux 省往返），mock 按命令子串（`__NODE__` / `grep -m1` / `is-active` / `systemctl --user stop`）区分。
- 健康检查只验证「隧道上取到任何 HTTP 响应」：远端对无凭据 `GET /` 应答 401（index 由 browser-auth 保护），按状态码判定存活会把正常的隧道误判为失败（实际发生过）；单元 active 且内容未变时 launch 复用旧实例（`reuse:`），重试连接走 `is-active` 判定不叠加新进程。**复用实例健康检查不过 = 实例病了**（旧就绪行还在、HTTP 不应答）——重启自愈一轮回环；新启动实例失败属环境 / 转发问题，报错不自愈。
- 实例版本判定的事实源是**进程自报的启动时刻快照，不是磁盘当前版本**：`getDshRuntimeVersion()` 与插件 package.json 都是运行时读磁盘，而部署段在判定之前就把磁盘升级了——运行时读取会报出「新版本」而进程跑着旧代码，升级判定被完全骗过（假阴性）。快照必须在模块加载（= 进程启动）时定格：`localDshVersion`（顶层 await import）与 `localPluginVersion`（顶层 IIFE 读 package.json）都是模块级常量，远端实例与宿主复用同一份代码、同一语义。将来若把更多事实纳入判定（对齐面扩大），同样必须快照化，禁止在 `/version` 处理器里现读磁盘。
- systemd 托管下的停启语义：正常停启走单元（stop = cgroup 整组收进程，MCP server 一起退，`TimeoutStopSec=15s` 有界收尾；无需 pid 身份核验——systemd 按单元定位进程，不存在 pid 复用误杀）。**旧 nohup 形态的迁移清理保留 pid 身份核验**（`ps -p $lp -o command=` 含 dsh 才杀）：升级插件后首次连接，旧形态实例还在跑，直接 restart 会叠加双实例（`--port 0` 各占一个端口，不会失败只会悄悄分裂）——启动命令先按 pid 文件核验身份、有界等待（SIGTERM → SIGKILL）整组杀掉再废弃 pid 文件。日志截断两道防线：stop 后 `: > log` + 单元 `ExecStartPre` 每次启动（含 Restart= 自动拉起）先截断——旧就绪行不清掉，下次 poll 秒命中死实例的旧 token。
- systemd 用户服务的环境差异：用户管理器的默认 PATH 极简（nvm node、uv/npx 全不在）——单元必须整体注入探查到的登录 PATH；ssh 非交互会话的 `XDG_RUNTIME_DIR` 通常由 pam_systemd 注入但不可依赖，命令前置 `${XDG_RUNTIME_DIR:-/run/user/$(id -u)}` 兜底；linger 刚开启时用户管理器可能未起完，`daemon-reload` 有界重试（10 次 × 1s）覆盖该窗口；单元文件内容随每次连接按最新探查重建（dsh 升级换路径 / 用户改 PATH 都经 cmp 检出后 restart 生效）——不要缓存「已写过单元」的判定。
- 远端 web 实例的配置 HMR 常开（base 组合包的 hmr 行只在无 profileContext 时禁用，web 模板不覆盖；headless / sdk / acp 等 stdio 一次性应用才显式禁用）：dsh-hmr 监听 profile package.json（bundles 清单变化重整 loader 树，新装插件是进程未加载过的新模块、正常 require）与两层 cordis.patch.yml；MCP 同步写的是 mcp.json，由远端 dsh-mcp 的文件 watcher 在线跟进。模块级热替换（root）默认关且与同步无关——同步写入的生效不经过实例重启，keep-instance 断开语义与 HMR 无耦合。
- 本地转发（`ssh -N -L` 子进程）不随宿主进程退出而亡，泄漏防线三层：runConnect 开头杀旧句柄（重连覆盖句柄前必须 kill）；`fail()` 分流——同步操作失败且连接仍在（running 非空）时保留转发、阶段回 running（操作失败 ≠ 连接中断；旧行为清 running 不杀进程，正是「隧道在而面板未连接」的一个根因），其余失败杀转发清 running；`ctx.effect` 挂 `engine.dispose()` 兜底正常退出。宿主被 SIGKILL / 崩溃仍会漏——转发租约 + load 清扫兜住（`src/forwards.ts`）：杀前经 `killOrphanForward` 核验命令行仍属本插件形态（防 pid 复用误杀，核验工具缺失则留待下次）。注意同一 `$DSH_HOME` 起两个宿主实例会互相清掉对方的转发。排查：`lsof -nP -iTCP -sTCP:LISTEN | grep ssh` 对照 GET /dsh-remote/state 的 `running.localPort`，活跃转发以外的都是泄漏。
