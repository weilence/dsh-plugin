# @weilence/dsh-remote

DSH web 插件：设置页新增「远程开发」菜单——把一台远端机变成完整的开发机：工作区、Bash、终端、LSP、MCP server 全在远端执行，本地只保留浏览器界面。

每个连接有三种登录方式（新建 / 编辑表单里的「登录方式」）：

- **SSH 别名**：填 `~/.ssh/config` 里的主机别名（可点「选择…」从清单里挑，清单由本机配置只读扫描而来）。认证完全交给 ssh 配置——密钥、ssh-agent、证书、ProxyJump 全部照旧生效；**该别名必须已经能免交互登录**，本插件不会为别名补密码（`BatchMode` 下 ssh 不提问，认证失败时面板会提示改配密钥或改用密码 / 密钥文件方式）。
- **密码**：填地址（IP / 域名）、端口、用户与登录密码。密码经 `SSH_ASKPASS` 递交给 ssh，不进命令行参数、不出现在任何面板响应里。
- **密钥文件**：填地址、端口、用户与本地私钥路径（支持 `~/`）；私钥设了口令时再填「私钥口令」（同样经 `SSH_ASKPASS` 递交）。手动方式统一按 `StrictHostKeyChecking=accept-new` 处理主机密钥：首次自动记录，密钥变更时硬失败并提示人工核对。

口令默认只在本次运行内有效（宿主重启后点「连接」会弹框要求重新输入）；勾选「记住口令」才写入 `$DSH_HOME/dsh-remote.json`（文件权限 0600，密码明文，面板上有明示），可随时「清除已保存的口令」。表单底部有「测试」按钮：不保存也能先验连通性，结果以一次性 toast 显示（node / npm / dsh 版本或失败原因）。

管理远端机上的完整 dsh web 实例：

- **连接**（内含远端部署）：探测 node / npm / pnpm（pnpm 缺失时显式失败并提示在远端手动安装，不做 corepack 自动启用）→ 远端 dsh 版本对齐本机（`npm install -g @deepseek-ai/dsh@<本机版本>`；对齐目标是本机**现读**的已装版本——本机升级了 dsh 而宿主还没重启，连接也能直接把远端升上去；本机版本探测失败时直接中止部署，不回退安装 npm latest。方向感知：远端比本机**新**时不降级、照常连接，面板提示「本机版本落后」建议升级本机，不做强制）→ 安装本插件：先对比远端已装版本与 profile 登记，一致则跳过；不一致才本地 `pnpm pack` 打 tgz（发布语义打包，workspace 协议依赖自动落成具体版本）经 ssh 推到远端 `~/.dsh/dsh-remote/payload/` 并 `dsh plugin add <tgz>` 安装，随后读回 node_modules 里的版本确认。无 scope 的包名 `dsh-remote` 在 npm 已被第三方包占用，本插件走 `@weilence/*` scope 且不依赖 registry。部署完成后启动实例：远端实例由 **systemd 用户服务托管**（单元 `~/.config/systemd/user/dsh-web.service`，随连接自动生成；`loginctl enable-linger` 让它在 ssh 退出后常驻、开机自启，崩溃由 `Restart=on-failure` 自动拉起）——单元已 active 且内容未变的旧实例是复用候选，经隧道问它自报的运行版本（`GET /dsh-remote/version`，进程启动时定格的快照）与本机比对——dsh 一致（或远端更新）且插件一致直接复用（秒连，token 不变）；dsh 落后于本机（本机已升级）或旧实例未带版本接口或复用实例无响应时自动 `systemctl --user restart` 收敛一次，新进程加载刚升级的磁盘。远端没有 systemd / 用户总线不可达 / linger 开不了时**显式报错**（不做 nohup 回退）。实例监听端口由本插件选定并写进单元：首选 3080（dsh web 自己的默认端口），被占用时按候选表换一个，之后始终沿用单元里的端口——端口稳定，systemd 重启（自动拉起 / 版本收敛 / 手动 restart）后本地隧道与浏览器会话才能无缝续用；日志里的 `dsh web: <url>` 就绪行只用来取 token。启动后远端有界循环等待就绪信号，本地 `ssh -N -L` 端口转发 + 健康检查——连接成功以 toast 提示，**不自动打开网页**，经卡片上的「打开」按钮进入 `http://127.0.0.1:<local>/?token=…`（鉴权、loopback 校验对转发端口照常工作）。已装齐时部署段立即完成。
- **远端实例常驻，无「断开」操作**：本地转发随宿主退出或意外中断消失，远端实例作为 systemd 用户服务继续在后台运行（linger 已开，远端重启后随用户管理器自动拉起），下次连接复用秒连。**一台机器只有一个实例**：单元名固定为 `dsh-web.service`，不随本地连接（别名 / 地址）变化，同一台机器换个别名连也复用同一单元；要彻底关闭远端实例，在远端执行 `systemctl --user disable --now dsh-web.service`。「删除连接」只清除本机记录、已保存的口令与端口转发，远端实例与已装产物保留。
- **存活心跳、版本漂移与自动恢复**：面板打开期间每 10s 对远端实例做一轮「测试链接」查询（全走既有隧道，不新开 ssh）：`GET /`（应答 401 也算活着）+ `GET /version`（实例自报的 dsh / 插件版本，实时刷新到连接行上）。连接行因此直接显示 `node / npm / dsh / 插件` 版本与端口映射（机器事实来自连接时的部署探查，实例身份由心跳实时刷新），**不再展示打开用的 token 链接**——「打开」按钮照常可用。心跳顺带做**版本漂移检测**（semver 比较，基准是本机现读的已装 dsh 版本）：远端落后于本机时卡片出现「远端可升级」徽标与「升级远端」按钮——确认弹窗明示两侧版本与「远端实例会重启、进行中的会话会中断」，确认后走与连接相同的完整流程把远端 dsh 与插件对齐到本机版本（正在使用的会话请在升级前保存工作）；本机落后于远端时只显示「本机版本落后」提示建议升级本机 dsh，不做强制、不降级远端。连续 3 次（约 30s）无响应才建一条 ssh 向 systemd 核实，按事实分三路——`activating`（systemd 正在拉起）标「实例重启中」继续观察；`active`（进程在但不应答）标「实例无响应」，不盲目重启以免丢现场；`inactive / failed`（被手动 stop、崩溃循环触顶、机器重启后 linger 失效）自动重跑一遍连接流程把实例拉起，成功后回「运行中」并 toast「已自动恢复」。同一轮掉线最多收敛 3 次，超限判死并附 systemd 状态与日志尾部；核实命令本身失败（网络断开、宿主休眠恢复中）按「状态未知」降级，不做任何动作。端口固定之后，systemd 自动拉起的实例回到同一端口，已打开的页面靠浏览器会话 Cookie 自行恢复——多数重启无需面板介入。
- **同步**（Skills / MCP / 插件 / 系统提示词四类，**只往远端新增 / 覆盖，永不删除远端内容**）：连接卡片上的「同步 ▾」下拉选类别（无需先连接：Skills / MCP / 提示词只需 ssh 可达；未连接时同步插件会先弹出「连接远端」引导弹窗），弹窗实时读取远端清单并与本机逐条比对：列表 = 本机清单，差异 / 新增 / 无法比对项默认不勾选（勾选才同步）；已一致项同样默认不勾、但可自由勾选——勾选即**强制重推**（行尾绿色「已一致」徽标醒目标示），配合右侧「隐藏已一致」开关（默认开，只影响显示）与左侧「全选」（只作用当前可见行）：取消隐藏后勾选已一致项提交，即强制把本机内容重新推到远端。未勾选与远端独有条目不受影响。同步完成（或失败）以 toast 提示结果摘要。远端清单读取失败时按「无法比对」降级展示，仍可同步（无删除风险）；要清理远端内容，用远端实例自己的 Skills / MCP 管理面板。连接过程不做任何同步；写入的内容在实例在线时通过 HMR 生效，实例未运行时在下次启动时生效。
  - **Skills**：两个用户级根（`~/.dsh/skills`、`~/.agents/skills`）按内容指纹（全部文件的 sha256 折叠，隐藏文件不计）比对，差异技能 tar 单向推送。
  - **MCP**：勾选的本机 MCP 服务器声明（含 env 凭据，面板明示）按生效配置签名比对，差异行整块合并进远端 profile 的 `cordis.patch.yml`（按 serverName 对齐，远端手写行被覆盖时替换为本机行）——cat→改→cat 的原子 round-trip，手写注释与无关行原样保留；全部一致则不写盘。
  - **插件**：逐插件比对「远端激活状态 + 版本号」（npm 语义：版本即内容契约，本地传输与远端下载同判）后分流——本地路径安装（link / file）的插件永远本地 `pnpm pack` 打包传输（未发布的开发版本也能同步到远端），npm 依赖形态的插件按弹窗选项选本地传输或远端自行下载（精确对齐本机版本）。同版本换内容不会被识别——改了代码要同步到远端，先 bump version。
  - **系统提示词**：单文件同步——本机用户级 `~/.dsh/system-prompt.md`（与「系统提示词」面板管理的同一文件）按内容 sha256 比对，差异时以 tmp+mv 原子写入远端 `~/.dsh/system-prompt.md`；远端实例需装有 dsh-prompts 才把它注册进系统提示词组装，写入的内容在下一次尚未开始的模型步骤读取。

环境同步能力集中在本插件面板里——dsh-skills / dsh-mcp 保持纯本地管理插件，不感知远端，功能各自独立。会话迁移使用 [dsh-sessions](../dsh-sessions/README.md) 的「会话迁移」面板；本插件提供复用现有 SSH 隧道的认证传输通道。本机与远端都需启用 dsh-sessions，本机需使用包含该通道的新版 dsh-remote。会话迁移只新增或跳过一致内容，不采用上述环境同步的覆盖语义。

## 前置条件

- 本机 `ssh`（Windows 10+ 自带 OpenSSH 客户端）、`tar`（bsdtar）与 `pnpm`（插件同步 / 部署的打包走 `pnpm pack`；须在宿主进程可见的 PATH 上，GUI 启动不继承 shell 配置时请独立安装）；ssh / tar 缺失时面板顶部告警并禁用相应操作，pnpm 缺失时打包动作显式报错。
- 三种登录方式至少可用一种：能免交互登录的 `~/.ssh/config` 别名（密钥 / agent / 证书），或远端账号的密码，或一个本地私钥文件（有口令也可）。
- 远端 Linux + systemd ≥ 240（`systemctl --user` / `loginctl` 可用，且能为本用户启用 linger——远端不支持时连接显式报错；macOS 与无 systemd 的环境不受支持）+ Node ≥ 22.19（部署时检查并给出指引，不代为安装 Node）。

## 安装

```bash
dsh plugin --profile <name> add @weilence/dsh-remote
```

（或手动把 `@weilence/dsh-remote` 加入宿主 `package.json` 的 `dependencies` 与 profile 的 `dsh.profile.bundles`。）安装后重启宿主生效；宿主启用 HMR 时刷新设置页即可。

## 行为边界

- 远端产物固定四处：`~/.dsh/dsh-remote/`（实例日志、askpass hook 与插件 tgz payload）、`~/.config/systemd/user/dsh-web.service`（实例的 systemd 用户单元）、`~/.dsh/profiles/<name>/`（插件安装与 patch 写入）、两个用户级 skills 根。
- 删除连接只删本机记录、已保存的口令与转发租约；远端产物保留。
- 口令只存在于三处：勾选「记住」时的 `$DSH_HOME/dsh-remote.json`（0600）、宿主进程内存、发给 ssh 子进程的环境变量（`SSH_ASKPASS` 通道）；面板、`/state`、进度与错误详情里都没有明文。
- 密码 / 私钥口令与别名方式一样按命令逐次认证（不做 ControlMaster 连接复用）：一长串远端命令会有多次登录，但不会互相复用凭据。
- 远端实例重启后 token 必换，旧 URL 失效；端口不变（写死在单元里），浏览器 cookie 仍有效，刷新页面即可回到会话。
- stdout 的 `dsh web:` 行是唯一机器可读就绪信号，格式无版本契约——本插件只从它取 token（端口以单元为准），解析失败时面板回显远端日志尾部供人工判读。
- 实例端口首选 3080，占用时自动顺延（3081–3089，再不行取内核分配的临时端口）并写进单元；端口只在单元里没有有效值（首次连接或旧版 `--port 0` 单元）时才探测，不额外打扰运行中的实例。
- 本地隧道端口同样稳定：每个连接按 id 确定性占首选段 13080–13111 的一槽（跨重连 / 宿主重启回到同一端口，书签与按端口写的外部规则不失效），首选口被占时回退内核临时端口，槽位空出后自动回到首选；`ssh -L` 带 `ExitOnForwardFailure=yes`，绑不上立即退出并换口重试，不留空隧道。
